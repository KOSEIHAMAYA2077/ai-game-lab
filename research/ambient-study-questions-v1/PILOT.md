# 未実施の最小人間評価案

**目的は初期問題の発見。** PCで文書・創作・プログラミングを日常的に行う成人6人を将来対象にする案だが、今回0人・募集0件・実施0回。6は資源制約と全6順序を一度ずつ観察する形成的選択で、十分な統計的検出力や非劣性を保証する数ではない。人数は推論目的と必要情報に結びつける。[Lakens 2022](https://online.ucpress.edu/collabra/article/8/1/33267/120491/Sample-Size-Justification)

## 実施前のgate

1. candidate source / 設定 / 表示サイズ・位置・背景・明度・色・seed / taskと採点 / 欠測扱い / 収集schemaを固定する。今のR2一覧labを3D小窓と呼ばない。有限rendererへの同一ID読取接続、文字面の視認性、停止 / hide / 復帰が未確認なら、欄の分かりやすさだけを評価する。
2. 自作欄の実DOM・主要ブラウザ / IME列を先にQAする。未対応trace / 5秒失効 / blur noACK / body容量を明示し、実利用可能範囲を決める。module回帰合格を一般IME成功の代わりにしない。
3. 研究用人工文章と原稿だけを使う。私的作業文書・既存全文の読取不要。本文loggerや `inspectVolatile` の実入力保存へ接続しない。誰が何を保存し、いつ消すかを説明し、隠す / 終了 / 任意中止を許す。

以下の100units、8分、約50分はこの計画の提案値。文献が最適と保証した値ではない。人を呼ぶ前の校正で変更したら、新版として理由を記し、本試遊の結果を見て課題・指標を選び直さない。

## 初回は表示一要因だけ

| 条件 | 表示 | 共通の固定状態 |
| --- | --- | --- |
| O / Off | 非表示 | 同じ内部状態・同じ保存off。主課題レイアウトを変えない |
| S / 静止 | 文字表面の静止 | 人工文字100units・同じ固定球・同じ色・カメラ・窓サイズ/位置/明度 |
| M / 穏やかな動き | Sと同じ面の固定した動き | 文字追加・内容解釈・形変更・fps / 明度 / 配置調整は比較へ入れない |

参加者の入力はこの初回の表示を駆動しない。初期bodyは同量、上限以内から開始し、各条件で同じ状態へreset。時間固定の人工変化を入れる後の試験でも、master replayの時刻を使い、参加者の速度 / pauseへ依存させない。replayのcontrolled境界を明示し、本人の痕跡が価値を持ったという結果へ転用しない。

条件中に隠す・中止は常に可能。hidden時間を除いた率だけで条件比較すると「嫌で隠した」負担を落とすため、予定8分内の実数 / 中断 / hide / 中止を主表にし、可視時間は別併記する。再表示を強制しない。

約50分: 用途・収集説明5分、練習5分、3×8分、各条件後2分（計6分）、自由試行 / 面接10分。休憩・中止で実時間は変わる。主課題は一種類、例えば固定原稿の文書修正だけに絞り、同難度の等価3セットを別に事前確認する。創作文の品質・本職の生産性として一般化しない。

次は登録前に固定する割当候補。A/B/Cは同じ種類の等価原稿で、参加者を行へ無作為割当する。各条件×セットは2回、各periodの各条件 / 各セットも2回。各行は条件・セットを一度ずつ使う。この均衡は課題難度一致・持越し効果消失を保証しない。条件が1行のセットに固定し続けるわけでもない。

同じ原稿の反復練習はしない。各条件は同じ固定の事前説明、同じ終了指示で始める。表示が気になるかを条件中に頻繁に質問し、注意を誘導しない。面接者の期待や条件を隠せない観察の影響も限界として残す。

## 最小収集と分母

| 測るもの | 収集 / 分母 | 解釈の限界 |
| --- | --- | --- |
| 主課題 | 固定採点の誤り・完了秒、未完了 / 中止。予定条件時間と実時間 | 未完了を最大時間の完了と偽らない。小課題の成績で自由創作 / 生産性を断言しない |
| 停止 | 事前定義した停止episode実数・秒、刺激との時間的重なり、本人の事後説明 / 原因不明 | 例えば2秒閾値は独自候補。停止と刺激の近接だけでは因果にしない。episode数を人数へ足さない |
| hide / reopen | 予定条件内件数・hidden秒・中止理由。可視秒も別表 | hideが多い条件を可視時間当たりだけで軽いと判定しない |
| 主観 | 邪魔・見返したい・好み各1〜7、具体的理由、不要だった場面 | 独自質問、検証済み尺度ではない。三つを合計の成功点へしない |
| 入力理解 | 後述自由試行で期待した / 実際の変化、unknownやholdを理解できたか | 明確要求のaccepted precisionやambient意味正解率とは別 |

eye tracker・動画・画面常時収集を既定にしない。目視の粗い方向分類を行うなら一部を二人で独立符号化し、不一致を残すが、視線計測や注意の直接測定と命名しない。初回は主課題成績・停止・hide・本人の理由で足りる。[Bakker et al. の方法と限界](https://pure.tue.nl/ws/portalfiles/portal/17749128/07370024.2014.921531.pdf)

NASA-TLXを採用する次版では、正式manual・6尺度・加重 / 非加重を先に決める。上の独自3問をTLXと呼ばず、公式道具の利用を今回実施したとも言わない。[NASA公式](https://www.nasa.gov/human-systems-integration-division/nasa-task-load-index-tlx/)

各人×条件の値を示し、差、中央値、範囲、失敗episodeと理由を記述する。18条件runを独立18人と数えない。成功0件 / 失敗0件も件数と露出時間を併記する。n=6で「差なし」「無害」「生産性改善」「統計的有意」「非劣性」を採択条件にしない。将来の確認研究は最小意味ある差・必要精度 / 検出力・母集団を別に定める。

## 別の10分試行：入力とのつながりと削除方針

研究用の短い原稿だけを専用欄へ入れ、known追加、変換cancel、削除、undo、色変更を一度ずつ試す。body / docの上限以内、初期baseline0、same-event echo重複0を実際の範囲に明示する。主課題の比較成績へこの学習試行を合算しない。capacity / noACK / 長いIME列は別QAまたは任意説明例にし、全部を50分へ詰め込まない。

append保持が現在の暫定候補であると伝える。人工例 `ABC→AC` の身体が `ABC` のまま残る案と `AC` になる案を、提示順序を入れ替えて説明する。文書同期は実装済み製品UIと偽らず、既存全文取込・色/ID再割当の不確実性も述べる。

誘導を避けて「入力欄の削除後、身体はどうなると思ったか」「どの状態を残したいか、その理由」「分からなかった変更」「見返したい / 不要だった場面」を尋ねる。本人の回答前にappendを好ましい既定と決めない。体験の好みだけで技術的な取りこぼしを相殺しない。

## さらに後の問い

内容連動の価値は、同じ入力・候補列のschedule比較と、本人の入力に反応する自由試行を別にする。後者はlive exposureが内生的で、入力数で割るだけでは交絡を消せない。引用 / 否定の字句誤反応は正解率へ隠さず、本人の解釈と不一致の具体例として扱う。60形 / 6primitive / 3字句群を同じ分母へ合算しない。

長期試用は新規性、慣れ、非使用・再開、持越し履歴の影響を調べる別案。現body256のまま5日 / 8hを自然利用できると仮定しない。上限 / eviction / 保存 / resetの選択を先に決め、その選択で痕跡体験が変わることを記録する。任意の数日使用でも習慣・長期愛着を証明しない。原文 / ID列 / 色順を研究者へ出さず、集計と本人の理由だけを基本にする。今回はその接続、募集、実施をしない。
