# 保留付きの既知形解釈を比較するプロトコル

2026-10-03の設計提案。数値目標と新しいデータ件数は本計画の選択であり、達成値や先行研究の標準値ではない。

## 一つの主RQと二つの副RQ

**主RQ:** 低資源の文字表面ウィジェットで、既知の6基本形を明示的に指定する日本語を、誤作動を抑えてどこまで正しく受理できるか。

評価する判断は、形ラベルを一つ返すか、保留するかである。明確な保留対象での誤発火率を制限した動作点において、表現可能な要求の正しい受理率を比較する。常に保留する方式は誤発火0でも、正しい受理0なので有用な解とは扱わない。受理範囲を狭めることで誤りを減らす考え方はselective classificationの研究に対応するが、既存実装がその論文の手法や保証を実現したとは扱わない。[Geifman and El-Yaniv, 2017](https://arxiv.org/abs/1705.08500)

**副RQ1:** 局所の訓練・開発集合にない言い換え、および否定・引用・取消・非対応の対象に対し、特徴方式と共通の範囲規則は、正しい受理と保留のどこを変えるか。

**副RQ2:** 解釈処理を必要な入力時だけ動かし、文字の蓄積と表示を分けることで、元の文字・色・同一性・表面を保ちながら、実窓の資源予算と形成時間を満たせるか。

資源予算未達でも主RQの比較は成立する。ただしその方式を「ウィジェットで実用可能」とは結論しない。解釈が未達でも軽い描画の工学的結果は残せるが、意味理解の成果へ置き換えない。

## 主課題の入力と出力

主課題は日本語の一つの要求から、sphere、box、tube、ring、blade、vaseの一つ、またはholdを返す。既存tinyのcylinderはtube、torusはringへラベル表記だけ対応させる。名前の別名による集計の重複を避ける。

| ラベル | 事前に人間へ示す対象の定義 |
| --- | --- |
| sphere | 球状の一つの立体 |
| box | 箱状の一つの立体。主課題では立方体と直方体の寸法差を指定しない |
| tube | 円柱状の一つの基本形 |
| ring | 通常の円環。メビウスや結び目を含めない |
| blade | 既存の刃形の一つの基本形 |
| vase | 既存の花瓶形の一つの基本形 |

注釈前に、六つの標準形の画像と寸法・表現範囲を固定する。物体名がこの表に自然に対応しない場合、人間が無理に最近傍の形へ割り当てない。複数部位、関係方向、個数変更、厳密な寸法・ねじれ・局所断面の指定は主課題の範囲外とする。対象外の要求を、指定を落として単体にした出力は保留失敗である。

出力は`label | hold`、範囲規則の理由、raw top1、各ラベルのscore、margin、実際にモデルへ渡したquery、token IDまたはfeatureの識別子、処理時間とする。scoreを正解確率として表示しない。信頼度の数値と実際の正解確率の一致は別の校正課題である。[Guo et al., 2017](https://proceedings.mlr.press/v70/guo17a.html)

本文の蓄積は解釈の成功条件にしない。hold、例外、遅い返答でも、入力した文字は一度だけ材料として残り、既存の文字と色を失わない。古い入力に対する返答を新しい身体へ適用しない。

## 明示操作とambientの分離

全入力が素材になることと、全入力に命令の実行意図があることは異なる。研究用の明示モードは、利用者が形の操作を選んだときだけ主課題の判定を行う。普段の文章に球や箱という語が出ただけで、明示要求として採点したり自動実行したりしない。

| 項目 | 明示モードの主研究 | ambientモードの将来研究 |
| --- | --- | --- |
| きっかけ | 利用者が形の操作を選ぶ | 確定した文章の安定した窓、蓄積量、一定の待ち時間 |
| 文字の身体への追加 | 解釈と独立して即時に追加する設計 | 同じ。意味処理の待ち時間で文字蓄積を止めない |
| 意味からの形変更 | 受理した要求の形を提案する | 内容との緩やかな関連を低頻度で反映する候補 |
| 保留の意味 | 指定を実行しない | 今の姿を保持する。本文は蓄積する |
| 正解 | 六つの形またはholdの注釈 | 一意の正解形を強制しない。関連性、変化の納得、頻度、作業の妨げを評価 |
| 現在の証拠 | fresh120・140の限定した命令課題 | 現在の評価は支持していない |

ambientの初期設計候補は、確定した直近60秒程度の文章だけを端末内で集計し、同じ候補が複数の窓で続いたときに変更し、変更後は120秒程度姿を保つ方式である。これらの秒数は未調整の提案で、命令fixtureへ合わせた値ではない。短い語一つや引用で頻繁に変形する設計、文全体を毎フレーム推論する設計は比較対象としても負荷と変化頻度を明示する。文字量による成長と意味による形の変化を別イベントにする。

ambientでは、通常文への「誤った命令実行」を命令分類のfalse positiveとして混ぜない。要求されていない変更の回数、気を取られた回数、取り消し・停止操作、文章との関連についての本人の判断を独立に記録する。まずアプリ内の合成文章の入力・再生で比較し、OS全体の取得や私的な仕事の本文を今回開始しない。取得APIの調査と、この研究プロトコルの実行は別作業である。

## 比較条件

以下は**将来の同条件比較**であり、既存の別々のfixtureから方式の優劣を決める表ではない。

| 条件 | 特徴・予測 | 学習と調整の記録 |
| --- | --- | --- |
| C0 | 明示語・別名の規則 | train/dev由来の語彙のみ。語彙数と規則の数を保存 |
| C1 | 小さい文字n-gram等の線形分類器 | 新しいtrainのみで学習。feature、量子化、seed、epochを凍結 |
| C2 | 固定した日本語静的埋め込み128次元 | 同じ6形のcaption集合。事前学習と本課題の調整を分ける |
| C3 | 同じ静的埋め込みの1024次元 | C2と同じcaption、query、token ID、pooling。mmapを別の実装条件として記録 |

主比較では全文の同じquery、同じ長さ上限、同じ六つのラベル、同じ範囲規則、同じ出力適用処理を使う。名詞を切り出す既存tinyは別のlegacy診断として残し、全文方式との違いを「埋め込みだけの効果」としない。既存tinyの切り出しを使う場合は、全方式へ同じ切り出しqueryを渡す補助比較を別に設ける。

C1とC2/C3は事前学習の情報量が異なるため、同じ局所データ予算でも「表現方式だけの因果効果」とはしない。配布可能な方式としての受理と資源の比較が主目的である。外部の事前学習の有無・規模が不明な部分、caption数、別名数、train/dev由来の情報、調整した試行数を開示する。C2対C3のdimension比較だけは、同じ学習済み表のprefixと同じtoken IDで統制する。

形の候補を返す特徴部と、命令範囲の規則を分ける。raw argmaxを記録した上で、各方式のdevで凍結した動作点を比較する。共通規則の有無を調べる補助比較は、**同じscore閾値のまま規則だけを切り替える**。既存staticのretrieval_only/guardedは別々に校正された閾値なので、差を純粋な規則の効果と呼ばない。

開発時の選択規則は、明確な保留での誤発火を先に抑え、その範囲内で正しい受理率を高める、と事前に固定する。最終集合を見る前に一つの主候補とC0との主比較を指定し、残りは副比較とする。C2とC3は同じ開発予算・caption数を使う。float16は元の128-float32との決定差と資源差を調べる数値実装の比較で、別の意味理解方式として水増ししない。

## 正解と失敗の定義

| 注釈 | 成功 | 失敗 |
| --- | --- | --- |
| 表現可能で一意の正例P | 正しい一つの形を受理する | 別の形を受理する、要求を落として受理する、holdする |
| 明確な保留N | holdする | どの形でも受理する。これを誤発火FPとする |
| 曖昧A | 主正解率へ加えない | 受理数と出力を別報告。複数解を後から正解にしない |
| 実行不能・数値失敗 | 本文を保存し形変更を保留する | 例外、非有限geometry、本文・色・IDの損失、期限外の古い返答の適用 |

Nは、対象への禁止・取消、引用や仮定の言及、非要求の説明やcode、未対応物体、範囲外の構成、相互に矛盾する指定の六群に分ける。否定が色や説明だけにかかる正当な形要求はPとして別の難しい群を用意する。否定語の存在だけで全て止める規則に成功を与えない。

主結果は、正しい受理TP/P、正例の受理A+/P、正例の保留数、正例内の受理精度TP/A+、誤発火FP/N、全ての明確な入力での受理精度TP/(A+ + FP)、raw top1正解/Pを並べる。全体正解一個で合成しない。曖昧Aの受理はこれらの分母から外す。

誤った受理は望まない形変更と修正操作を生み、正例のholdは操作のやり直しを生む。この利用者側の損失を試遊で別に記録する。誤発火一件と保留一件を同価値と決めた総合正解率だけで採否を決めない。損失に重みを付ける補助分析を行う場合は、重みを事前登録して複数の仮定を示し、6人の感想だけで全利用者の費用を確定しない。

リスク対受理範囲の曲線は事前に決めた閾値列について診断として報告する。最終集合から都合のよい閾値を選び直して主成績にしない。学習のないscore、softmax、cosineの値を同じ確率尺度と仮定しない。

受理精度はP:Nの比率で変わる。主集合のP:N=1:1を明記し、P:N=1:9および9:1の再重み付けを**仮定した頻度での感度分析**として併記する。日常文章の実測比率とは呼ばない。例えばTP/P=t、正例の受理率=c、FP/N=f、正例比率πなら、明確な入力の受理精度はπt / (πc + (1−π)f)である。形要求が稀なambient入力へ、1:1の精度をそのまま移せない。

実験の候補目標はFP/N≤5%、TP/P≥60%、明確な入力の受理精度≥95%とする。これは採用を判断するための提案であり、現在の方式が満たした値ではない。各群の件数と区間を示し、有限の合成集合で上限以下だったことを、あらゆる文章の安全保証とは言わない。予測器の方法差を論じる主比較は、同じ入力でのTP/Pの差を用い、保留群の違反を添える。

## 訓練・開発・最終未見・人間評価を分ける

現在のfresh120とfresh140は、新しい変更に対する**回帰集合**とする。失敗を見て次版を設計することはできるが、その同じ文で未見性能を主張しない。既存のtinyは全文一致が0でも実際の分類queryに大量の訓練重複があったため、全文だけの監査を再利用しない。

新しい計画の最低件数は次の通り。著者の時間を見積もるための案であり、特定の検出力が保証される件数ではない。

| 集合 | 正例 | 明確な保留 | 曖昧 | 用途 |
| --- | ---: | ---: | ---: | --- |
| train | 360、各形60 | 240、各群40 | 0 | C1の学習、C0語彙とC2/C3 caption設計の許可範囲 |
| dev | 120、各形20 | 120、各群20 | 30 | 閾値、規則、方式選択、長さと数値条件の調整 |
| 最終未見 | 180、各形30 | 180、各群30 | 60 | 一回の主評価。全文も実queryも実装者から隠す |
| 試遊用 | 独立の練習と作業課題 | 独立の試遊課題 | 必要なら別に記録 | 操作、妨げ、好み。最終未見の文を転用しない |

同義語・語彙族、文型・paraphrase族、同じ作者の派生シナリオにgroup IDを付け、文を分ける前に群ごとに分割する。単語の新しさだけでなく、「既知語の新しい文型」「局所train/devにない言い換え」「正当な要求中の別対象への否定」を事前の層とする。最終未見には一群につき一つの主文を入れ、追加の近い派生文は補助成績にする。例文の言い回しと正解をモデル出力から逆算しない。

二人の人間が、固定した六つの形と範囲定義を見て、モデル出力を見ずに独立注釈する。不一致は件数と理由を残し、候補評価前に合意するかAへ移す。人間が難しい文をAI一人の正解で確定したと扱わない。作者・注釈者と試遊者を可能なら分け、AIを使った文案には生成条件と人間による採否を記録する。

最終未見の保管担当は実装者と分ける。ソース、重み、caption、規則、閾値、input crop/normalization、label定義、採点仕様、方式選択、実行環境のhashを先に凍結する。最終集合に試遊中露出した文は評価前に識別し、その群を回帰用へ移して新しい独立群を用意する。露出を隠して残さない。

出力後、全文の完全一致と正規化一致に加えて、**全ての実モデルquery**とtrain/devの重複を調べる。関係headを使う補助課題では、そのマスク後queryも監査する。意図的に切り出し語が重複する群と、重複しない群を別に報告する。公開されていない事前学習集合との非重複は検証できないため、「未知語理解」ではなく「局所train/devにない表現での性能」と記す。

最終評価は全件の生出力と失敗を保存し、件数、率、方式間の同一入力での差を示す。群単位の再標本化で差の不確実性を調べ、作者やテンプレートを独立な多数人の標本と見なさない。二項区間を出す場合は文の独立性を仮定した参考値と明記する。希少な誤発火を0件観測しても母集団の率0とは結論しない。学生研究の中心は、固定した有限の比較集合と失敗の再現可能性とする。

## 補助課題と将来の主張

60形検索は、作者が用意した60 enumへ対応する別課題として別表を作る。near-familyの許容は評価前に固定し、正解の60分類と6primitiveを同じ分母にしない。6形Programの二部位＋関係は、構造・寸法・関係方向・schema内/外を別々に採点する。今回の主課題の成功を、これらの成功へ拡張しない。

将来の対象部位や断面半径を予測する局所編集headは未実装の研究案である。学習、独立評価、部位同一性、表面の接続、実時間を検証するまでは、この夜間作業で達成したと書かない。任意物体、未知語の一般理解、text-to-mesh、ambient文章の一般的な意味理解は主張に含めない。
