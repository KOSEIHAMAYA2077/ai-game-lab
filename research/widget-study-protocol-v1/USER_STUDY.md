# 6人による探索的試遊の手順

2026-10-03の実施案。被験者への連絡・募集・試遊は開始していない。所属先の人間参加研究の手続きに従って実施する。6人は最初の操作と妨げを見つける資源上の選択であり、一般ユーザーの好みや生産性を統計的に証明する人数ではない。人数は推論したい範囲と得られる情報に合わせて説明する。[Lakens, 2022](https://online.ucpress.edu/collabra/article/8/1/33267/120491/Sample-Size-Justification)

## 参加者と試遊条件

日本語の文章入力とPCの基本操作ができる成人6人を対象にする。開発者・fixture作者・最終未見の注釈者は試遊者へ含めない。可能なら普段の作業が文章中心の人3人、プログラミング等を含む人3人にし、経験差を記録する。これは層別の効果を推定する人数ではない。

全員が同じ実験機と同じ窓位置を使う。持ち込みの仕事・日記・私的な本文は求めない。研究者が用意した合成メモ、短い文書編集、短いcode修正をアプリ内で行い、OS全体の入力取得は使わない。休憩、停止、非表示、途中終了をいつでも選べる。入力の記録範囲と保管期間を同意説明に明記する。

方式の意味精度は[主プロトコル](PROTOCOL.md)で先に凍結する。人間試遊は別の文章と課題を使う。最終未見集合を試遊へ出して、後から未見と呼ばない。試遊で見つけた例に合わせた変更は次版と回帰集合へ分ける。

## 約50分の一回の試遊

| 時間の目安 | 実施内容 | 目的 |
| --- | --- | --- |
| 5分 | 説明、同意、通常の作業とPC経験の確認 | 条件と記録範囲を共有する |
| 5分 | 合成文で入力・停止・形の選択を練習 | 操作の初見だけで条件差を作らない |
| 15分＋短い回答 | 表示3条件を各5分、独立の編集課題 | 作業中の妨げと文字の蓄積の見え方 |
| 12分＋短い回答 | 形操作2条件を各6分 | 提案を使う操作と直接選択する操作の違い |
| 8分 | 振り返りと自由な追加入力 | 納得できた変化・分かりにくさ・続けたい状況 |

表示の3条件はD0小窓なし、D1文字の身体が静止、D2同じ文字の身体が穏やかに流れるものとする。D1/D2は意味による形変更を止め、同じ標準形と文字追加を使う。まず描画と蓄積そのものの妨げを調べる。意味の自動変更を同時に変え、差を動きだけの効果とはしない。

D0/D1/D2の六つの順序を、6人へ一つずつ割り当てる。編集課題は難度が近いA/B/Cの3版を先に準備し、条件との対応をずらす。同じ文章を三回編集して記憶による速度差を作らない。実機の条件、文字数、窓の寸法・位置、fps、音なしを揃える。条件順と課題版の割り当てを試遊開始前に保存する。

形操作の2条件はI0既知6形の直接選択、I1明示文からの提案と「適用」の確認とする。I1は凍結した一つの候補を使い、予測した形名を見てから適用できるようにする。hold時は本文だけ残り、形を変えない。アプリの現在の標準処理を自動モデルへ置き換える試験にはしない。この確認操作を含めた時間を測るので、モデル推論時間とは呼ばない。

I0→I1を3人、I1→I0を3人にする。各条件は一意の要求8件と保留を意図する操作2件を、異なる課題版で用意する。単語を暗記して入力する課題だけにせず、標準形の図を見て自分の表現を一度使う課題を含める。その文章は試遊資料として保存する。正解は固定した対象形、保留課題では形変更なしとする。これは10件ずつの形成的課題で、主評価の代わりにはしない。

## 観測と質問

計時中のthink-aloudは、作業速度や注意を変えるため必須にしない。終了後に画面内のイベントを振り返る。研究者はOS全体の画面・キー入力・他アプリの本文を記録しない。

| 観測 | 定義 |
| --- | --- |
| 編集課題の結果 | 完了時間、指定箇所の正誤、残った修正、未完了 |
| 形操作の結果 | 正しい適用、誤提案、誤提案の適用、hold、直接選択への切替、修正回数 |
| 操作負担 | 提案を見てから適用まで、形の再変更、停止・非表示の使用 |
| 注意 | 小窓が原因で作業を中断したと本人が述べた場面、研究者が観測した窓への操作。視線を計測していない場合は視線回数と呼ばない |
| 履歴保持 | 入力文字が増えたこと、旧色・旧文字が残ることを認識できたか |

各条件の後に、1から7で「作業を続けやすかった」「気を取られた」「入力が身体に残ることが分かった」「変化が納得できた」を別々に尋ねる。この4項目は本計画の質問で、妥当性が検証済みの心理尺度ではない。平均だけで合格にせず、参加者ごとの値と自由回答を残す。

最後の自由回答は「作業のどの場面で置いておきたいか」「止めたくなった場面はどこか」「入力と変化のつながりが分からなかった場面はどこか」「次に何を加えてみたいか」「形の提案を確認する手間はどう感じたか」とする。面白い・役立つという答えへ誘導しない。肯定・否定の原文を匿名化し、同じ参加者の発言と数値を対応できるIDで保持する。

6人の結果は、中央値・個人差・条件順・観測した失敗・自由回答のテーマを中心に報告する。6人×複数課題を多数の独立参加者とみなさない。人口一般の効果や有意差を狙う次の研究では、最小の意味のある差、個人内のばらつき、必要な精度・検出力から、人数と解析を事前に決める。

## ambientの評価は次段階にする

この短い試遊は、日常文章の内容から身体が穏やかに変わることを実証しない。ambientの次の比較は、文字の蓄積と動きを共通にした上で、B0意味変更なし、B1低頻度で安定した窓からの変更、必要ならB2より頻繁な変更を比較する。命令の正解形を強制せず、本人にとっての関連、姿の安定、望まない変更、停止した理由、作業とのつながりを聞く。

最小の追加案は、同意した6人が各5作業日、アプリ内または明示的に提供した合成/共有可能な文章で使い、毎日2分程度の記録と最後の面談を行うこと。これは一週間の探索であり、慣れた後の継続使用を保証しない。長期の生活・仕事への取り込みを主張する段階では、数週間以上の実使用と新奇性の変化を調べる。ambientの評価を短時間の命令成功率だけで置き換えないという方法上の指摘は著者の一次資料にある。[Pousman and Stasko, 2007](https://faculty.cc.gatech.edu/~john.stasko/papers/pervasive07-eval.pdf)
