# 文字表面のサイドインテリア：HCI 本文調査 v1

2026-10-03 JST。調査・比較設計の資料であり、アプリの採用判定や人間評価の結果ではない。

公開レビューで描画3形・有限Programの6基本形・根性60形の区別を一箇所明確にした。[ROOT-PUBLICATION.json](ROOT-PUBLICATION.json) に元文書と公開文書のSHAを残し、[SHA256SUMS](SHA256SUMS) は現在の公開ファイルを検査する。論文の原票と出典は変更していない。

創作・プログラミング・仕事の入力から育つ文字表面を、必要なときに見返せる作業の痕跡として設計する案を整理した。全入力を命令に読み替えず、**文字の蓄積、文章内容の穏やかな反映、明示した形変更命令**を別の経路にする。黒い空間と3D文字の面を品質条件に置く。

文献が支えるのは「反射的に注意を取らず、時間を経て関わり直せる表現を検討する理由」と「評価を短期成績だけにしない理由」である。Glyph Matter の生産性改善、快適性、未知語理解、任意文章からのメッシュ生成、新規性を達成したという根拠にはならない。Informative Art と Slow Technology の著者も、単純な認知負荷低減とは異なる目的を説明している。[本文を含む大学公開再録](https://gupea.ub.gu.se/server/api/core/bitstreams/1275020c-8af5-4805-8172-314ae851a656/content)

最初の具体的比較は、同じ文字・同じ既定形・同じ動きで、現在の浮く黒い窓と小角窓の遮蔽・文字面の読める大きさを調べる。細い端配置、隠せる窓、背景配置、透過も候補に残すが、文字面を潰す条件は採用しない。Task Bar Hero の開発元は作業窓を覆わない底部配置を説明しているが、こちらの常時最前面窓と同じ条件ではなく、タスクバー配置の優位性を実証した論文でもない。[開発元の説明](https://www.nugemstudio.com/en/games/taskbar-hero)

次に、文字蓄積だけの条件と、安定した文章窓から低頻度で形を変更する条件を比較する。内容解釈器を先に調整したり、既存の未見120例・140例へ合わせ直したりはしない。アプリ既定へのモデル採用見送りは維持する。

既存の [研究プロトコル](../widget-study-protocol-v1/README.md) は既知形の明示要求を扱う別の研究案であり、この文書で置き換えていない。60 authored shape と6 Program の母数も分ける。現在の実装・描画比較・soak の最新状態は root 所有の文書を参照し、この調査の測定結果として加算しない。

このフォルダ以外の資料・ソース・依存・Git・UIは変更していない。OS全体入力取得、Dock/作業領域変更、被験者募集、試用、外部送信は開始していない。無料公開 PDF は読取用の無視対象 `.cache/` に置き、原論文や図を配布資料に含めない。
