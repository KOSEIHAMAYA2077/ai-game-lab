# 骨格から肉付けする、約10秒の生成案 v0.1

2026-10-02 / Glyph Matter。ユーザーの追加条件「生成は10秒程度」「骨格だけ作り、決めた範囲で肉付けする方式でもよい」を反映した設計。以前の研究と試遊版は保持する。**今回確定したのは目標と次の比較範囲であり、この方式の10秒達成や意味精度はまだ実証していない。**

[前段の研究とCPU評価](16gb-text-to-3d-20261002.md)では、小LLMの推論は動いたが意味精度は不足した。出力を骨格へ縮めるだけでその問題が解決したとは扱わない。

## 方針

文章 → 小モデルが形状族・寸法・曲がり・部品関係を読む → 決定的な処理で中心線／部品構造を組む → 規定範囲の太さと断面で肉付け → 文字を表面へ配置して流す。

モデルには全頂点や自由なPythonコードを生成させない。中心線の自由座標も最初は出させず、長さ、曲率、ねじれ、部品の接続を短いパラメータとして返す。配置処理が具体的な中心線を計算する。骨格の種類、半径・厚み、滑らかさ、接続方法は自前の規則として管理し、少数の連続値で形を変える。

ここでの「骨格」は形を組み立てる中心線・部品グラフ。動かすための関節骨格とは分ける。鳥・魚・蛇の動きは、まず保存済みのrigへ対応させる。未知の動物の汎用rig自動生成は初回範囲に含めない。

## 最小の比較対象

| 対象 | 小モデルが決めるもの | こちらで行う肉付け |
| --- | --- | --- |
| 花瓶 | 胴・首・口の比率、膨らみ、縦横の尺度 | 正の半径を持つ断面を軸周りに回転。内外面と口・底の扱いを決め、文字の表面座標も持つ |
| 剣 | 刃・柄・鍔の構成、長さ・幅・反り | 中心線に沿って扁平な断面を押し出し、柄と鍔を規定の接続で組む |
| 輪／ねじれ輪 | 半径、帯幅、曲がり、ねじれの量 | 既存の円環・メビウスの曲面族を使い、継ぎ目と文字の移動を管理 |
| 球・立方体 | 尺度、伸長、角張り | 既存形を比較基準として使う |

初回の上限案は4部品、中心線1本につき8制御点以下。初期表面は低い分割数で構築する。これらは未実測の設計値で、意味や見た目が崩れる場合は上限を増やす前に形状族と処理を分ける。

曲線に沿う面の基礎は[Three.js TubeGeometry](https://threejs.org/docs/pages/TubeGeometry.html)、軸対称な花瓶は[LatheGeometry](https://threejs.org/docs/pages/LatheGeometry.html)、断面の押し出しは[ExtrudeGeometry](https://threejs.org/docs/pages/ExtrudeGeometry.html)が参考になる。TubeGeometryそのものは一定半径なので、変化する太さや接続面には自前の処理が必要。既製APIだけで関節・面の接続・循環が完成するという意味ではない。

## 10秒の定義と予算

**入力を確定してから、新しい表面に文字が載って最初の完成描画が出るまで約10秒**を目指す。モデル推論だけを10秒と数えない。表示後も文字は流れ続ける。

| 工程 | 最初の予算案 |
| --- | ---: |
| 前処理 | 0.3秒 |
| 言葉の解釈・構造推定 | 6.0秒 |
| 範囲・参照・接続の検証 | 0.2秒 |
| 骨格と表面の構築 | 1.0秒 |
| 文字の対応付けと初回描画 | 0.5秒 |
| 余裕 | 2.0秒 |

合計10秒。これは設計上の配分であり、16GBノートや現在のMacで全工程を測った結果ではない。起動・モデル読み込み・初回生成と、準備済み状態の生成を別々に測る。ダウンロード時間は生成とは別に明示する。

処理中も前の形と文字を動かす。別Worker／別プロセスで計算し、検証した新しい結果だけを画面へ交換する。本文、文字ID、入力順、指定色は保持する。範囲・参照の不正や時間切れを検出した場合は前の形を保つか既知の形へ戻すが、その代替表示を新規生成成功と数えない。未知の意味の誤読を全て自動検出できる前提は置かず、意味の一致は評価でも確認する。

## 確認するもの

- 未見の人工入力で、形状族、数、寸法、部品の関係が意図どおりか。以前の24文は回帰確認用に保ち、調整後の未見精度には使わない。
- 骨格だけでなく肉付け後の形も確認する。剣の刃と柄、花瓶の口、輪の穴やねじれをそれぞれ見る。
- 全工程のp50/p95、10秒超過率、時間内かつ意味の正しい生成率、代替表示率を別に記録する。
- 初回と暖機後、CPUとiGPU、RAM・共有GPUメモリ、描画停止を分ける。M5・32GBでの測定は16GB Intel/AMDの実証としない。
- 文字が面を覆い、継ぎ目・部品接続・変形で途切れないか。文字を流す速度や静かな変形は生成モデルから分離する。

次の比較は、既知の骨格族＋属性推定を基準にし、形・属性・関係を分けて学ぶ小さいhead／構造decoderを追加する。自由座標JSONを再導入するより、短い意味情報と決定的な肉付けを組み合わせて検証する。
