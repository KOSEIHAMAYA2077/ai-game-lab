# 次の比較案：意味反映の寄与を一つずつ確かめる

未実施の提案。現在の model/threshold を調整したり、既存 fixture へモデルを再実行したりしていない。表示・入力契約・privacy が通るまでは専用欄と人工 replay に限定する。

## 比較する問い

問いは『命令を何%当てるか』から、『同じ文字面と同程度の変化に、内容との関連が加わると、本人は何を感じ、何が邪魔になるか』へ分ける。明示 command の既存精度評価はそのまま別に必要である。

第一段階は既存候補を固定したまま、本人が任意に top-k を覗ける小さな比較案とする。top3 hit41/60は新しい好みの成功値ではなく、この段階を調べる理由の一つだけ。

| 段階 | 固定するもの | 観測・採点 | 得られない結論 |
| --- | --- | --- | --- |
| A: 候補の関連性 | 新しい研究用文章 window、input mode、topic・除外条件、有限inventory、既存固定候補/source。人が候補を見る前に注釈 | 複数の許容association集合、明示target、特に望まないshape、判断不能を分離。top-k関連・unwanted候補・hold・不一致理由を別件数 | 人間0の人工ラベルを実ユーザーの許容と称すること |
| B: 表示の寄与 | 同じ文字/ID/色/面・camera・形の使用回数・transition・総変更数、同じ課題/文章列 | 関連したように感じた、見返したい、好み、望まない意味、邪魔、隠した時点、操作負担。課題の停止を別に観察 | 一つの総合点、生産性改善、低CPUだから快適という結論 |
| C: 本人の継続使用 | 同意した source、本文収集なし、pause/隠す自由。期間・露出/入力時間を記録 | 置き場所・非使用・再開・見返し・嫌だった連想を短い任意日誌で確かめる | 短期の新鮮さから長期愛着や定着を結論すること |

A では人が書いた研究用文を使う案を優先するが、今回募集・収集していない。注釈する人に正解の強制選択を求めず、複数形または『関連形不要』『判断できない』を許す。shapeの絵を見てから都合のよい target を付ける後付け採点は避ける。注釈者間の違いを失敗として消さず、本人の個別許容と集団合意を区別する。

同一 source-document・paraphrase・template group を train/dev/heldout で分ける。ここで読んだ120/140/student120とこの分析例は既知資料。次版の開発に使った文を、その次版の未見評価と呼ばない。caption/profile の直語一致と新しい全文の意味反映も separate に数える。

## B の三条件の候補

| 条件 | 表示内容 | 比較する寄与 |
| --- | --- | --- |
| T: trace | 同じ蓄積文字が同じ基準shape表面を流れる。shape class は変更しない | 文字の作業痕跡だけで十分か |
| P: periodic control | 同程度のshape変更をするが、文章に関係しない事前schedule | 変化や目新しさだけの寄与 |
| A: association | 固定 candidate の低頻度候補から、安定した内容windowと対応する形へ | 文章との対応に付加価値があるか |

最初は artificial replay の shape列を事前に固定し、P/A の総変更数・shape使用回数・保持/遷移時間を揃える案にする。P は A の候補列を時間順に並べ替えるなどで作れるが、偶然本文に合う可能性や順序効果を記録する。Aが元々holdした窓をPだけ頻繁に動かせば、頻度と意味を混同する。Tは変更数が違うので『変化ありの総効果』の基準であり、意味だけの因果比較はP/Aに限定する。

同じ人工本文を replay しただけでは、本人の書いた言葉が自分の痕跡になる価値を検証できない。Bの後、専用欄の自由試行やCで別に確かめる。また A の top-kを人が選ぶ場合は自己選択・操作負担が加わるため、無操作のP/Aと一つの順位へ合算しない。

表示3形・nativeの実装済みgeometry・Web根性60形・6 Program は別 inventory。比較で実際に描画できるものを明記し、描画3形の認識を60shape意味精度としない。型付きProgramが作れても、side interior の見た目が元版を上回ったとは言えない。

## 採否は性能と好みを分離する

関連候補が良くても、文字面が線だけになる・色やIDを失う・shapeが窓外へ切れる条件は表示の品質失敗。低CPUであっても閃光や大きな飛散が邪魔なら別の失敗。停止/取得除外を無視する動作は好みで相殺しない。

意味関連の低頻度処理、geometry変形、描画、入力受理のそれぞれを計時する。モデル table8 MiB、lookupが短いこと、100分CPU CLI の待機観測は、窓全体のRAM/電力・一般16GB laptopの達成とは別。人の測定は工学soakと合算しない。

本分析から即座に標準を変えない。次の実装を行うなら別versionで、固定 candidate/表示controller/入力契約のどこを変えたかを記録し、新しい目的・指標・人工例/人間例・threshold固定順を結果前に決める。現 default 不採用を維持したまま、まず候補提示と周期変形の研究比較を検討できる。
