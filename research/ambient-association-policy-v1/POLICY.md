# 入力モードと、形を動かす権限の候補

全て未実装の提案。現アプリの producer・body・モデル・閾値・保存・取得権限を変更していない。

## 本文と control を同じ経路にしない

| 経路 | 本人が何を期待するか | 解釈の成功/失敗 | 形に対する権限 |
| --- | --- | --- | --- |
| 文字を素材として蓄積 | 許可した確定文字が今までの言葉に加わる | 元の文字/ID/色・確定品質。削除した文の保持は蓄積の定義として別途明示 | 形変更の意味判定を待たず、唯一の body へ一回受理する。未知commitは素材化しない |
| 明示 command | 本人が形変更用の操作として送った要求を実行 | target、個数、属性、関係、取消・保留。既存有限 inventory 内だけ | 本文の解釈 score で command 権限を獲得しない。操作元で command 経路を選ぶ |
| ambient association | 仕事の内容に関連する、本人が解釈して楽しめる変化 | 関連の許容、望まない連想、安定性、邪魔さ。唯一の正解を常に要求しない | 短い端末内 window の候補。変更を低頻度に限定し、不明なら現在形を保持 |
| 内容と無関係な periodic | 文字面が一定周期で変化すること自体を楽しむ | 面の品質、動きの好み、妨げ、停止可能性 | 内容理解と表示しない。ambient の寄与を比較する対照にも使う |
| 停止/隠す/取得元除外 | 本人が操作を止める・見せない・取得しない | 確実な受理と継続禁止。美的な曖昧さを許容しない | 明示 control を優先し、model/periodic が勝手に解除しない |

仕事の文章に『中断する』と書いたことだけで app を停止する、といった隠れた command は提案しない。逆に、本人が停止ボタンを押した後、本文が花について触れたから再表示する挙動も許容しない。どの内容が素材になるかを取得元と入力モードで選べることが前提である。

## 引用・否定・code はモード依存

以下は分析用に新しく作った人工例で、評価 fixture や人の許容ラベルではない。今後開発へ使えば既知例になる。

| 人工本文 | command 経路 | ambient で未確認の可能性 | 残すべき制約 |
| --- | --- | --- | --- |
| 「本の中に『立方体』という語が出てきた」 | shape 命令とは扱わない | 本の話題として箱への連想が許容されるかもしれない | command を実行したという説明を付けない |
| 「角のない、丸い器を描写した」 | 属性を満たす有限形なら要求として扱える | 球/花瓶など複数の読みがあり得る | 文全体に否定語があるだけで失敗と決めない。現固定 guard は変更しない |
| 「この場面では剣を登場させない」 | 剣を作る命令ではない | 不在が主題でも、剣の出現を嫌う人もいる | 本人が避けたい形とした場合は候補から除外。『剣』keywordだけで許容を主張しない |
| `sphere = createMesh()` の説明文 | 本文の code を app command としない | プログラミングの話題として球が関係し得る | code 内の secret/パス/他者本文の取得・表示可否は別問題 |
| 「どちらも決められない。魚か鳥のような何か」 | 一つへ勝手に確定しない | 候補複数・保持・穏やかな中間表現が作品になり得る | 未検証の融合面を追加したとはしない |
| 「さっきの形変更を取り消して」 | 明示 command としての取消なら従う | ordinary 本文中の他対象の取消と区別が必要 | 明示 control の取消は保留・periodicで無視しない |

既存評価で quotation/negation/code を no-shape にした期待は、その評価目的に沿って保持する。新しい ambient 目的へ移す場合は事前に mode/許容関係を注釈し、古い誤反応を後から正解へ振り替えない。特に『期待 target と違う』と『望ましくない』は別の評価項目にする。

## 候補、保持、周期変形の調停案

一つの表示 controller が形変更を決める。本文受理/ACK/素材ID allocator とこの controller を分離し、モデル待ちで本文受理を止めない。model に新しい body allocator を作らせない。

- 最新の明示指定・本人による固定を優先する。固定中は ambient/periodic が上書きしない。
- ambient 候補は、低頻度でまとめた同じ window の top-k。同じ候補が続くなら変更せず、低信頼/競合は保持。最大3候補などは比較用の案であり採用値ではない。
- periodic は別の選択肢。ambient が意味候補を出さない時に動かす案と、意味形の class を保ち面だけ変形する案を分ける。timer が必ず shape class を変える仕様にはしない。
- hide/pause 後の推論回答は windowRevision/session/epoch で stale として無作用にする。再開で過去の候補をまとめて追いかけない。これは既存契約の考え方を将来接続へ持ち込む提案で、現 native 接続済みを示さない。
- 新 shape へ移る時も、過去の文字・ID・色を保持する。shape switch 回数、blend duration、camera/視点の速度を別パラメータとして検証する。

既存 HCI 資料の60秒 window・最短120秒保持などは仮説的候補で、今回最適値として選ばない。描画の15fps、model評価の頻度、geometryの変形時間も別の時間である。

## 本文 privacy と、連想が生むコスト

文字を surface に見せることは、全文保存を off にしていても周囲から本文の一部が見える可能性を持つ。形ラベルも作業の主題を間接的に示す。外部送信なしや原文ログなしだけで匿名化できたとは言わない。

| 項目 | 提案する扱い | 確認できていないもの |
| --- | --- | --- |
| 取得範囲 | 自作欄/明示連携から始め、許可した source だけ。取れない本文は取得できたと扱わない | 全アプリの確定本文を普遍的に得る API、実OS/IME capture |
| private/sensitive 作業 | secure/password field・除外app・本人のpauseは素材化/推論しない。sourceが判定不能なら本文を読まず活動量のみ、または保留 | 自動 secret 検出だけで漏出を防ぐこと、OSでの全 source 判定 |
| 短い意味 window | 端末内 volatile buffer、上限と期限を明示。モデルの scores/本文返信をそのまま log へ書かない | raw/vector/window を保存しない実装の完成、全 copies の消去保証 |
| 素材の保存 | off/任意保存を区別し、保存先へ許された fieldだけ。offでも表示中の文字には本人が隠せる操作を残す | 既存の素材を削除したり自動浄化した成果。この分析では既存物を削除していない |
| 研究ログ | 照会/採用/保持/取消件数・時刻・同意した label・queue/資源の集計。人工例か本人が研究用に選んだ文だけを別途使う | 作業本文の常時収集、課題を見張ること、他者の本文を使う許可 |

誤連想のコストは一つではない。弱い関連が楽しい場合、テーマ違いが不快な場合、頻繁な変化が邪魔な場合、private な話題が見える場合、command の取消を無視する場合を分ける。後二者を美的好みの平均点で相殺しない。一方、引用やcodeを話題として見せること自体を全 mode で always wrong と固定しない。
