# 小窓の描画負荷を下げる比較計画

2026-10-03。v0.14 のソースを読み、次の比較版で変更する場所を絞った記録。ここにある容量と転送量は**ソースから計算した値**で、プロセスの実RAM、CPU使用率、GPU帯域の測定値ではない。改善率や予算達成は、実測するまで主張しない。

## 現在の計算経路

[`GlyphScene.render()`](../../prototypes/glyph-creature/src/scene.ts) は表示中の各文字について、毎フレーム次を行う。

1. 作者定義の曲面、骨格、または部位プログラムから材料座標の位置を得る。
2. 文字数による形成率、1.6秒の形の遷移、入力からの吸収を合成する。
3. 曲面の2接線を正規直交化し、文字平面の回転を四元数に変換する。
4. 文字中心と回転の属性をGPUへ送り、1つのインスタンス描画で表示する。

球・箱・メビウスでは位置と解析的な接線を同時に求める。[`surface-flow.ts`](../../prototypes/glyph-creature/src/surface-flow.ts) のこの経路は、すでに位置と方向の重複計算を避けている。部位プログラム、花瓶などの骨格面、拡張形、クラゲなどは、中心1回と接線用の前後4回、合計5回の曲面評価を行う。部位の形・面積分布はコンパイル時に作られており、毎フレーム生成し直しているわけではない。[プログラム面](../../prototypes/glyph-creature/src/scaffold-program.ts)、[骨格面](../../prototypes/glyph-creature/src/skeleton-surface.ts)、[拡張面](../../prototypes/glyph-creature/src/expanded-surfaces.ts)、[語の面](../../prototypes/glyph-creature/src/word-surfaces.ts)。

鳥・魚・蛇の骨行列は同時刻のパレットを共有し、文字ごとに骨階層を作り直さない。[`creature-rig.ts`](../../prototypes/glyph-creature/src/creature-rig.ts)。このキャッシュを壊す最適化は避ける。

## まず比較する変更A: 同じ位置・方向を軽く計算する

表示上限1,536文字でも、現在の10個のCPU配列は保存上限32,000文字分を確保する。GPUへ接続した属性にもこの長さが使われ、`needsUpdate`だけを指定している。Three.js 0.186.1 の `WebGLAttributes.updateBuffer()` は更新範囲がなければ配列全体を `bufferSubData` に渡す。[公式BufferAttribute](https://threejs.org/docs/pages/BufferAttribute.html)はコンポーネント単位の `addUpdateRange(start, count)` を提供する。`instanceCount`は描く数であり、確保・転送する属性の長さを自動的に縮めない。[公式InstancedBufferGeometry](https://threejs.org/docs/pages/InstancedBufferGeometry.html)。

| 対象 | 現在32,000文字分 | 表示1,536文字分 | 判断 |
| --- | ---: | ---: | --- |
| CPUの10配列、計25個のfloat/文字 | 3,200,000 bytes / 3.052 MiB | 153,600 bytes / 0.146 MiB | 表示容量へ縮める。保存側Matterはそのまま |
| GPUの7属性、計16個のfloat/文字 | 2,048,000 bytes / 1.953 MiB | 98,304 bytes / 0.094 MiB | 表示容量へ縮める |
| 毎フレームの中心3＋回転4成分 | 896,000 bytes | 43,008 bytes | 実際に使用する範囲だけ更新 |
| 上記を15fpsで渡す量 | 12.817 MiB/秒 | 0.615 MiB/秒 | CPU/GPU使用率の改善幅は別に測る |

実装候補:

- `SceneOptions` の表示上限から配列容量を求める。オプションなしの従来版は32,000を維持する。旧タグは変更しない。
- `center` と `surfaceRotation` の更新範囲をそれぞれ `0..count*3`、`0..count*4` にする。入力時だけ変わる色・字形・生年月日等も必要範囲を指定する。Three.jsが範囲をアップロード後に消すので、描画を省略した時に古い範囲が溜まらないよう管理する。
- 形成率の乗算と形遷移を数値3成分で行い、各文字の `p.map()`、`target.map()` を避ける。吸収済みの文字では `sources.subarray()`、`Array.from()`、吸収用配列を作らず、中心へ直接書く。吸収中だけ再利用する入力元・目標・結果のscratchを使う。
- 吸収の遅延と長さは `intakeSeed` から決まる。入力時に表示文字ごとに計算して持てば、定着した文字に毎回2回のハッシュを掛けなくてよい。リセット・表示標本の入れ替え時には同じIDで再計算する。
- `glyph.id` を曲面座標に使う現行仕様を保つ。表示標本が入れ替わると位相だけが変わる現在の `randomUnit(i * ...)` は、次の比較では `glyph.id` を使う候補。上限以下では `i === id` なので従来の見え方と一致する。

このAは15fpsの各描画時刻で、従来と同じ曲面位置・方向を求める。CPUの削減量は未測定で、WebKitの描画・合成の固定費が支配的なら5%予算に届かない可能性がある。

## 次の比較B: 曲面更新と画面更新を分ける

Aが不足した場合、**曲面を約5Hz、画面を15fps**で更新する別候補を作る。5Hzの座標をそのまま表示すると文字がカクカクするので、2つの時刻の位置・回転を用意し、頂点shaderで現在時刻へ補間する。

1. 定着時の材料座標の位置と回転を、現在区間の始点 `t0` と終点 `t0 + 0.2` で評価する。
2. 区間が進んだら前の終点を始点へ再利用し、新しい終点だけ評価する。
3. 画面は15fpsで更新し、位置の線形補間と四元数の補間、カメラ回転、色の新しさ等のuniformを更新する。
4. 四元数は `dot(q0,q1)<0` なら一方を反転してから正規化補間する。四元数の符号は姿勢と一意に対応しないので、そのまま混ぜない。
5. 最初の@、新規文字の吸収、1.6秒の形遷移ではAの毎回評価へ戻す。安定後にBを使う。停止・非表示では未来時刻の評価も行わない。

これは近似になる。曲面上の文字が補間中にわずかに面を外れる、接線が一致しなくなる、関節の近くが潰れる可能性がある。特にメビウスの接合、開いた面の縁、花瓶の内面・口・底、形の部位境界を優先して比較する。解析的なsphere/mobiusはAのまま、5回評価する形だけBにすることも比較対象。全形を一律に低速化しない。

追加属性にはGPU上限の確認が必要。現行はquadのposition/uvと7つのinstance属性で計9スロット。位置終点と回転終点を追加すれば11になる。起動時の `MAX_VERTEX_ATTRIBS` を確かめ、足りない環境はAへ戻す。CPU側の補間ならこの制限は避けられるが、15fpsの属性転送は残る。

別の中間案は、位置を毎回正確に求め、接線・回転だけ5Hzで補間する構成。数値微分を使う形では、曲面評価回数は15回/秒×5評価から、15回の中心＋5回×4接線評価＝35評価/秒へ減る計算。ただし姿勢が実際の曲面とずれるため、採否は同じ誤差・画面比較で決める。

## RAMの別候補: 字形atlasの初期容量

現在のCanvas atlasは、文字が@だけでも2,048×2,048。RGBA8換算の論理画素は16 MiB。Canvas、GPU texture、WebKit内部のコピー数は未測定で、この16 MiBをそのまま実RAMの削減量とは呼べない。

容量段階を持つ案では、32列を保ち高さを必要行数へ増やす。1行なら2,048×64で0.5 MiB、4行なら2 MiB、最大32行なら現行の16 MiB。tile IDと既入力の字形を保ち、shaderのatlas行数uniformと全表示UVを更新する。Canvasのresizeは内容を消すため、旧canvasを保持して新canvasへコピーし、Textureは新しく作ってmaterialに差し替える。古いGPU資源だけを解放する。保存済みの文字や利用者ファイルは削除しない。[公式Texture](https://threejs.org/docs/pages/Texture.html)は初回使用後のサイズ変更では新Textureを作るよう案内している。

これはCPU比較A/Bと分ける。1→2→4→8→16→32行の境界を越えた時、既入力の日本語・絵文字・結合文字が消えたりUVが別字になったりしないことを確認する。64pxセル・42px字形はまず維持し、見た目の品質と容量を同時に変えない。

## 正しさと測定の条件

人工文だけで以下を確かめ、入力の外部送信はしない。

| 条件 | 保つもの・見るもの |
| --- | --- |
| @だけ、16、256、1,536、32,000文字保存 | 保存個数・色履歴・文字ID、表示上限、有限座標 |
| 球、立方体、メビウス、クラゲ、鳥/魚/蛇 | 面を覆う2次元密度、文字平面が面から浮かないこと、骨格・拍動の連続性 |
| 花瓶、刃、箱を輪が貫くプログラム | 内面・外面・部位・ねじれの保持 |
| 白い旧入力→青い新入力→上限超え | 原文・旧色を保存し、新規色を描く。標本入れ替えを文字の消去と扱わない |
| 吸収の途中で形変更、停止、非表示、復帰 | 吸収が飛ばない、隠れている時間を急に追いつかない、非表示で更新0 |
| 回転・zoom・小窓resize | カメラのみの変更でモデル/全形コンパイルが走らない |

同じ400×440、pixel ratio 1、同じ文字種と表示数、同じ人工文・seed・時刻範囲でA/Bを比較する。暖機後のcalm状態を測り、入力中の30fpsは別に記す。`render()`の所要時間はJSとコマンド投入の一部であり、WebKit/GPUプロセス全体のCPU・GPU実行時間ではない。アプリ本体、WebContent、Networking、GPUを帰属付きで測り、Mach timebaseを使う実CPU集計とphysical footprintを併記する。

採否は、CPU・RAMが下がったかに加え、表面が線に縮退せず見えるか、滑らかさを維持するかで決める。Bは正確な時刻評価を基準に、投影した中心のずれのp95/最大、姿勢差のp95/最大、有限値と境界越えの連続性を記す。採用候補の暫定基準は中心誤差p95 1px以下・最大3px以下、姿勢差p95 2°以下とし、これは未達を隠すための事後調整をしない。

## 実験順序

1. v0.14を凍結・公開し、実測が未達であることを残す。
2. Aの容量・転送範囲・定着文字の一時配列だけを変え、同時刻の数値一致を確認する。
3. Aの小窓実測が改善したかを調べる。GPU/合成の固定費が強ければ別の実装を検討する。
4. 必要ならBを別候補にし、近似誤差・実画面・実CPUで比較する。
5. atlas容量は独立して比較し、字形の保存確認を行う。

この文書を書いた時点ではアプリコードを変更していない。共有測定への干渉を避けるため、ベンチマークは他の担当によるcalm/モデル/非表示の測定終了後に実行する。
