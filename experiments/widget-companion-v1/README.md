# 小窓の文字表面 v0.14.0-widget.1

[Web比較版を開く](https://koseihamaya2077.github.io/glyph-matter/widget-v1/)。旧4版を独立タグ/URLで保持した、新しい比較版。Macの常駐する窓は[ネイティブ側の作り方](../../desktop/glyph-widget/README.md)。完成物と検証結果はGitHub Releaseへ保存する。

## 操作

Enterで入力欄を開き、文章をEnterで送る。`白い表面 球体`、`青い表面 メビウスの輪`、`表面 クラゲ`など。HELPで「根性」と「小型モデル」を選ぶ。モデルは任意で、初回約128MBの公式ファイルを取得する。`細い棒の先に大きな球`など、最大2部位/1関係を端末内で解釈する。未知の形を自由に作るtext-to-meshではない。色指定はその入力の文字だけへ残る。

窓の位置と大きさは普通のMacアプリとして変えられる。メニューで手前表示を切替。閉じるボタンは非表示、⌘Qは終了。他アプリの文字入力を監視しない。画面下の透過帯・クリック透過はこの版にはない。

## 負荷を分ける構成

- AppKit/WKWebViewの400×440小窓。独自ブラウザランタイムを同梱しない。
- 通常15fps、文字の吸収30fps。停止/非表示/完全に覆われた窓では描画予約を取り消す。復帰時に隠れていた時間を一気に進めない。
- 描画サンプルを最大1,536文字に制限。32,000文字までの身体と原文・色は別に保持。古い文字の分布と新しい文字を選ぶ。最初の@を保つ。
- 入力/初回準備にだけ新しいモデルWorkerを作り、結果・失敗・中断で終了。ディスクの取得cacheと実RAMを分ける。モデルを常駐させない代わりに、入力ごとに再初期化する。
- localStorageへ原文バッチ/色/時刻/seed/形を保存する。アプリのポートが使用中で別originへ退避すると以前の保存状態が見えない場合がある。完全にoriginに依存しない保存は次の改善候補。

## 現時点の検証と制限

独立ブラウザ7人工入力、Worker再生成/終了、停止・非表示、復帰、色/原文を含む復元、中断後の再入力を検証。保存の文字種類上限に当たった時の復元失敗と、準備中断後のボタン回復を修正。詳細と測定範囲は[evaluation](evaluation/REPORT.md)へ記す。

初候補のこのMac測定では、球385文字/通常15fpsの4PID合算charged footprintはpeak約271.7MiB、1コア換算CPU約10.07%。200MiB/5%の候補予算は未達。初回モデル準備のsampled peakは約1,445MiB、処理後には約233MiBまで戻った。128MBのダウンロード量をRAM使用量と言い換えない。これらは短時間試験で、長時間安定性、GPUの電力、16GB laptop CPU/iGPUの実機動作を保証しない。

CPU・RAMを下げつつ文字の面を保つ比較、初回推論のピーク削減、自由文の取りこぼし、複数の形や語の関係、連続的な形の更新が残る課題。[研究の位置付け・先行研究・評価案](../../research/widget-research-map-20261003.md) / [8時間の現在地](STATUS.md)。

既存無料モデルの出所・SHA・学習済みheadは[部位Program版](../scaffold-program-v1/README.md)と同一。日本語IMEの一連の操作は未検証。実Macでは日本語pasteと送信、WebGL/Workerを確認しており、paste成功をIME検証と言い換えない。公開試験文は人工文だけ。
