# 文字ngram student — 最初の独立評価と規則版比較

2026-10-03 01:09〜01:12 JST。**小さな解釈器は短文を速く処理できたが、否定・取消・矛盾で5件の誤発火が残るため、freeze-1を既定の解釈器へ採用しない。** 同じ入力で既存の規則版より成功数は増えたものの、この差は学習だけの効果を切り分けた比較ではない。

評価担当は学習文・student実装・重みを見る前に90人工文と判定方法を固定した。モデル担当も評価文を見ないまま重み・閾値・処理を固定した。両方のSHAを検査して最初の推論を行い、その後に学習文との一致を調べた。完全一致の混入は10文あり、除外した**確定76文ではstudent54/76（71.1%）、規則版46/76（60.5%）**。これは小規模な人工ベンチマークの値で、任意の日本語・英語に対する正答率ではない。

## 技術と比較の範囲

studentは文字1〜5gramと英単語特徴を4096次元へハッシュし、int16量子化した線形softmax headで6primitive＋unknown、3関係＋noneを選ぶ。Transformer、LLM、ネットワーク推論、任意mesh生成は使わない。名詞の区切り・否定・属性・親子順は手書き規則である。

比較する規則版は、保存されている `ruleProgramResolution` の明示語・関係・属性規則。最後の変更commitは `50b12b6de0e9a27b4f93a9910aad1582071a43de`、source SHAは `1f10423d53cfdbbd384279804dd1430fa384ac746ac137dff6d61ba5a1d8cd01`。既存の60形の根性版全体の採点ではなく、同じ6primitive/最大2部品Programを出す小さな比較器を使った。

studentには規則版より広い名詞alias、異なるattribute規則、tube/bladeの異なる初期寸法もある。そのため、結果は**ハイブリッド解釈器同士の比較**であり、学習headの寄与や蒸留効果を証明しない。MiniLMをteacherとして学習したモデルではない。重いMiniLM版の90文比較は、native常駐計測との競合を避けるため今回未実施。

90文は確定render60、確定hold26、許容結果が複数ある曖昧4。主精度の分母は確定86文。曖昧4を主精度に足さない。

## 失敗と次の課題

全失敗は [overlap-and-comparison-v1.json](results/overlap-and-comparison-v1.json) に、入力・期待・全予測・分類とともに保存した。

**誤発火5文**は次の通り。どれも有効な有限Programなので、schemaだけを検査しても取り除けない。

| 入力 | 実際の受理 | 問題 |
| --- | --- | --- |
| 花瓶を取り消す | vase | 取消の扱いがない |
| 箱を出すな。 | box | 後置された禁止がguardにない |
| 管のない形 | tube | 「のない」の欠如指定を拾わない |
| 長くて短い棒 | tube、height0.65 | 矛盾を検出せず後の属性を優先 |
| A box that is both wider and narrower than itself. | box | 相反する比較語を処理しない |

規則版は上記5件に加えて「球は作らない」も誤って受理した。studentの単語分類が小さくなっても、意味上の安全性を一般化した否定理解で保証できるわけではない。

**親子逆転2件**は `Put a blade on the tip of a box.` と `Put a box on the tip of a blade.`。end関係のlabelは当てたが、`on the tip of` の向きを逆にした。規則版にも同じ2件の逆転がある。学習された接続labelと、手書きの親子方向決定を別々に評価する必要がある。

**属性5件**は「横に押しつぶされた球体」「縦に伸びた玉」「横に長い箱」「横に広いずんぐりした花瓶」「縦長の輪」。とくに「横に長い箱」は「長い」の規則でheightを大きくしており、方向の修飾を捉えていない。形labelの成功で属性の失敗を隠さない。輪や管のtwistについてはparamの非zeroを確認しただけで、知覚上の形の違いの良さは今回採点していない。

**見送り10件**は `s17, s19, r09, r10, r15, r16, r17, r18, r19, r20`。daggerや刀身、別節のend、より上、belowの反転などでprimitive/relationの閾値を超えなかった。閾値を下げればcoverageを増やせる可能性はあるが、今回残った誤発火との交換になる。最終評価へ閾値を合わせることを一般化の改善として報告しない。

**形状生成の拒否4件**は `r22, r24, r26, r30`。throughのcrossing childがbox/sphere/vase/boxで、既存コンパイラはtube/blade/ringだけをその役割に許している。Program schemaが6primitive×3関係を受け付けても、実際の幾何がその全組み合わせを作れるわけではない。次は解釈器にgeometry capabilityを伝え、未対応の構造は明示的にholdするか、別の有限コンパイラで対応する必要がある。意味の正答と安全な描画可能性は別の課題。

## 表面生成の確認

studentが受理した55出力中51は共通コンパイラで生成できた。規則版は48出力中45。生成できた各部品の表面と偏微分を、時刻0/7/19秒、seed41、128glyph点/部品/時刻と、各chartの端・中央で数値検査した。

- studentの表面サンプル合計35,136点、規則版32,112点。生成できた出力にNaN/Infinityはなかった。
- throughとして生成できた構造は、既存の複数時刻での材料占有サンプルが内外両方に跨ぐことを確認した。空洞だけを通ることや、外接箱の重なりだけを貫通成功と数えていない。
- これは有限数の数値検査であり、すべての時刻・入力・接触に対する数学的証明ではない。表面の視覚品質、文字の読みやすさ、ゼロに近い接線での描画品質、ブラウザのshaderはこのNode検査だけでは保証しない。

## 速度と資源の実測

Apple M5 / 32GB / macOS arm64 / Node v26.4.0、単一JS threadで90文を順に1回評価。入力は1〜50 Unicode code point、平均約13文字の人工短文。最初のmodel処理を含む。下表は解釈関数だけで、geometry検証や演出、画面更新は含めない。

| 時間 | student | 規則版 |
| --- | ---: | ---: |
| p50 | 0.055ms | 0.0038ms |
| p95 | 0.459ms | 0.133ms |
| 最大 | 2.575ms | 0.886ms |

student module読み込みは約1.672ms、展開したint16重み＋既知bitsetは91,136bytes。NodeプロセスのRSSはimport前約51.4MiB、推論中観測ピーク約60.3MiB。ただしfixture/予測配列、Node runtime、source parserやimportsなどを含む**harnessプロセス全体の観測値**であり、常駐アプリのRAMでもモデルの正味追加RAMでもない。JS heapとbufferとRSSを足してRAMと扱わない。geometry後GCのRSSは別に約74.2MiBとなり、この値にはgeometry処理も含まれる。[raw測定JSON](results/student-freeze-1-first-pass.json)。

4000文字の入力、毎回Workerを作って破棄する経路、Mac小窓のWKWebView/描画、長時間常駐、16GB laptop CPU/iGPUはこの測定では確認していない。解釈器だけの処理は低負荷候補になるが、ウィジェット全体の200MiB/CPU予算を達成したという主張には使わない。

## 混入検査と限界

初回推論後にだけartificial corpusを開いて完全一致とNFKC/小文字/空白整理後の一致を調べた。両方とも10文、すべてtrain側だった。該当idは `s06, s07, s10, s11, s16, s21, s26, s27, s30, h26`。両方式の同じ10文を除外した結果も併記した。学習担当がこの評価を見ていなくても、限られた形名の短文では偶然の完全一致が起こる。

除外後も、同じprimitive語彙・似た言い回し・意味familyの重複は残り得る。評価は手作業の90人工文、評定者1名、JA64/EN26であり、自然な執筆の分布を代表しない。「リングバッファ」のようなソフトウェア文脈や否定はholdするという保守的な期待で、単語に反応するアートの遊び方自体を否定していない。属性の数値条件も評価者が事前に決めた粗い意味方向で、ユーザーの見た目の好みを数値化したものではない。

## 次の比較

freeze-1のモデル・runtime・評価結果を保存し、既定採用は見送る。改善候補は否定/取消/矛盾・引用のguard、親子scope、有限コンパイラの能力に基づくhold。これを行う場合は新しいfreezeへ分け、今回の90文は**回帰評価**とする。

研究として学習headの効果を確かめるには、alias・attribute・順序規則を揃えたablationと、後から担当を分けて作る新たな未見文が必要。否定された一部だけを除外し「球ではなく箱」を成立させるscope、2部品の別々の属性、引用や比喩、曖昧な文への確認方式、視覚品質と常駐負荷の交換を次の課題にする。今回の失敗を足しただけの語句guardを、日本語理解の研究的な改善とは呼ばない。
