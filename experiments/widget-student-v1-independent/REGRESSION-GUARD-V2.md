追加された**引用guardは本90文に引用ケースがないため、この回帰では検証していない**。開発側の単体テストと、本回帰の根拠を混ぜない。新しい肯定例への過剰見送り、引用符を使った正しい形指定、複雑な局所否定は別の未見集合で調べる必要がある。

## 分類と追加規則の時間を分ける

Apple M5 / 32GB / macOS arm64 / Node v26.4.0。1〜50文字の同じ人工短文90件を1回ずつ直接呼び出した。ブラウザ・native appの処理速度ではない。

| 測定対象 | 件数 | p50 | p95 | 最大 |
| --- | ---: | ---: | ---: | ---: |
| 固定分類器（早期holdの0を含む） | 90 | 0.061ms | 0.353ms | 1.883ms |
| 固定分類器を実際に呼んだ入力のみ | 81 | 0.065ms | 0.433ms | 1.883ms |
| 追加規則、clone、validator、compile込み | 90 | 0.485ms | 2.219ms | 3.622ms |
| 関数全体の外側のwall clock | 90 | 0.559ms | 2.454ms | 5.584ms |

9文はglobal/contradiction guard等で分類器を呼ばなかった。guardMsは正規表現だけの時間ではなく、受理候補の形状コンパイルも含む。p95を別々に足して全体p95を作らない。元のstudentのp95約0.459msに対して全処理は重くなったが、この短文Node計測では最大約5.6msだった。

展開された分類器の重み・既知bitsetは元と同じ **91,136bytes**。追加規則のJS code、作業配列、shape compile、Node runtime、WKWebView、文字atlas、描画メモリはこの値に入らない。modelのダウンロード量やbuffer byte数を、native常駐全体のRAMへ読み替えない。AppKit小窓や16GBノートPCはこの回帰では未測定。[raw時間・メモリ観測](results/student-guard-v2-regression.json)。

形状probeは初回と同じ時刻0/7/19、seed41、各part/glyph/chartで行った。受理46出力のサンプル32,496点にはNaN/Infinityがなかった。生成できたthroughは既存の複数時刻の材料内外検査を通った。全時刻や描画品質を保証する数学的証明ではない。
