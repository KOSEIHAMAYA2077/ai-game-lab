# 色と構造の解釈を分ける

v0.13 の実操作で、色なしの `細い棒の先に大きな球` は動いたが、`白い細い棒の先に大きな球` は形を保持した。部品と寸法は正しかったものの、関係 head へ `白い` が残り、none の確率が約 0.89 になった。元の色失敗と head は v0.13 のタグ・実験記録へ保存し、この変更は別版で行う。

対応する 8 色（白/赤/黄色/青/緑/紫/水色/桃色、英語とシアン/ピンクの別表記）を、構造の解釈へ渡すコピーから除く。元の入力本文と文字は維持し、UI/描画は元の文章から色を選ぶ。文章を外部へ送らない。head の重み、閾値、6 部品の説明文は変更しない。

初めは関係 head の入力だけから色を除いた。その結果、部品・指定寸法・関係は CPU と WASM で 186/186 一致したが、未指定のねじれには 3 文で差が残った。`シアン` を含む部位の意味比較が twist=.65 を追加していたためである。この版の結果は `metamorphic-*-relation-only.json` に保持する。

続いて構造の解析全体で色を除き、句境界・否定・部位の意味・属性・関係へ同じコピーを渡すようにした。これによりモデルの関係へ色を混ぜず、形の属性も色だけで変わらない。文字そのものや色の選択をこの処理で消さない。

## 確認

- 8 色の日本語 23 表記＋英語 8 表記と、end / above / through の日本語・英語 6 文型を組み合わせ、186 文を実際に解釈した。言語の混在も含む。
- CPU と実ブラウザー Worker の両方で 186/186 を受理し、部品・明示寸法・関係だけでなく全 Program が色なしの基準文と一致した。
- 元の操作失敗 `白い細い棒の先に大きな球` は WASM で tube＋sphere＋end として動き、解釈時間は約 39.7 ms だった。文字の吸収・描画を含む全工程時間ではない。
- 英語の色の除外は ASCII の単語境界で揃え、redwood / whiteboard / blueprint / greenhouse / pinkish の一部を色として消さない。Python と JavaScript の `\b` が日本語との境界で異なるため、最初の失敗結果は `metamorphic-cpu-initial.json` に残した。
- 色つきの名詞否定、CJK の隣接色、英語の否定、同種の 2 部品で句境界と対象を保つ追加テストも行った。

これらは色を加えても構造が変わらないことを確認する開発/回帰テストであり、未知の自由な文章の正答率を示す独立評価ではない。3 部位以上や任意の物体への対応範囲は広げていない。元からある構文/意味解析の保留条件も残る。

変更前の source / head / config と hash は `frozen-v013/`、測定は `metamorphic-cpu.json` と `metamorphic-wasm.json` に保存する。head SHA-256 は変わらず `2b5e212a7b8fec5cbf9683620ba7883c77e74140ccb65a1e91bc5ca1f5618a87`。

実行スクリプトは `check_cpu.py`、`check_browser.mjs`、単体テストは `test_color_projection.py`。ブラウザー確認は frontend の開発サーバーで実 Worker を呼び、モデル準備と推論を実際に実行する。動作の境界を固定した旧版との比較に使用する。
