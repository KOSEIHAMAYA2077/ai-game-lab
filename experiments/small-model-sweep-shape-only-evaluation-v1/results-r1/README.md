# 形だけを選ばせる Fresh36 比較 R1

6候補を新しい日本語36文で独立採点した。Bonsai 4B Q1 は 28/36 の完全一致、Granite 4 1B は形を変える24文で 22/24 の一致だった。一方、**全候補で変形を保留すべき文への誤提案が残った**。今回の結果は、普段の執筆を無確認で変形へ結びつける既定モデルの採用を支持しない。

各モデルは1回ずつの逐次実行であり、生成の反復ばらつき、実ユーザーの好み、別PCへの一般化は測定していない。比較表は選定時の順序で、総合順位ではない。

保留文には通常の文章、引用・コード内の要求、明示否定、矛盾、未知対象、未対応の普通の輪、範囲外の個数が含まれる。誤提案数は契約適合した `propose` に限るため、「保留正解 + 誤提案」が12に満たないモデルには契約違反がある。

RSSはサーバー単独を250ms間隔で採った最大値で、短いピークを逃す可能性がある。UI・監視処理・OSのメモリ、GPUメモリは含まない。ファイル量を常駐RAMとして読まない。起動前の全ファイルhashがキャッシュを暖めるため、起動時間は管理されたコールド起動ではない。応答時間はHTTP要求から全文返信までで、純decode時間や入力から画面上の完成までとは異なる。終了直前の最後のRSS標本を、平常時やアンロード後の基準として用いない。

現条件の最小サーバー最大RSSも819.3 MiBであり、既に提案されたウィジェットの一時512 MiB枠より大きい。全体のCPU、idle、電力、実16GB laptopでの他作業との共存は未測定である。小さい型・低ビットという名前だけで「ウィジェット程度」と結論しない。

## 解釈と次の実験

Bonsai 4B Q1 は引用内の鳥、未知の自転車、球9個、花0輪で誤提案した。8Bは普通の輪や未知対象も保留できず、4Bより大きいことが今回の保留性能を保証しなかった。Graniteは外見記述と属性混在に対応しやすいが、文章中で対象名を述べただけの文やコードを変形要求として扱った。

次の段階は、有限形選択の候補としてこれらを残し、文章への単なる言及・引用・否定・未知対象・範囲外属性を止める処理を別に評価すること。決定的な規則とモデルを分担させる場合も、組み合わせた結果を新しい未見文と実利用で確認する。今回の36文に合わせて修正し、同じ36文で再実行した値は開発診断として別ラベルで残す。freshの主結果へ上書きしない。

資源については root が別ラベルで計算領域を縮める実験を行う予定。容量を下げた後も正しい形と保留を維持するか、起動・応答・サーバーRSSにどう影響するかを分けて調べる。この資料作成者はモデル起動・ビルド・ダウンロードを行っていない。

本試験が確かめたのは12種類の用意した形からの選択であり、任意の新しい3Dメッシュ生成、全OS入力連携、色・個数・動き抽出、文字テクスチャの視覚品質ではない。

## 凍結と再現
