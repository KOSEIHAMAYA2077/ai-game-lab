# 字形atlasの容量を段階化する候補

2026-10-03。小窓の文字表示で、@だけの時から全1,024種類分の字形画像を確保する構成を見直す。比較基準は[候補A](../widget-render-budget-v2/README.md)のcommit `6788869c79ae3fcda4777a81b4775ff6a6e363e6`。この候補は`dynamicAtlas: true`を明示した画面だけに適用する。指定しない従来経路は固定2,048×2,048のまま。

32列、64pxセル、42px字形、フォントと描画の色は変えない。列位置と文字IDを保ち、行数だけ1→2→4→8→16→32へ増やす。表示履歴と原文・色履歴を保持するMatterは変更しない。

| 文字の種類数 | 行数 | Canvas寸法 | RGBA8換算の論理画素容量 |
| --- | ---: | --- | ---: |
| 1〜32 | 1 | 2,048×64 | 0.5 MiB |
| 33〜64 | 2 | 2,048×128 | 1 MiB |
| 65〜128 | 4 | 2,048×256 | 2 MiB |
| 129〜256 | 8 | 2,048×512 | 4 MiB |
| 257〜512 | 16 | 2,048×1,024 | 8 MiB |
| 513〜1,024 | 32 | 2,048×2,048 | 16 MiB |

この表は論理容量であり、アプリ全体の実RAMやGPUメモリの減少量ではない。Canvas・Texture・WebKitのコピー、フォント、ランタイムの固定費は別に測る。

成長時には以前のCanvasと新Canvasが一時的に共存する。GPU資源の解放と、JavaScriptのガベージコレクション・OSによる実メモリ回収も同じ瞬間とは限らない。

## 保持と差し替え

Canvasをresizeすると内容が消えるため、新しいCanvasを作り、以前の画素を同じ位置へコピーする。新Textureを作ってmaterialへ渡し、旧TextureのGPU資源を解放する。利用者のファイル・文字履歴・既存アプリを削除する操作ではない。

Textureの寸法はGPUへの初回送信後に変えず、新しいTextureへ交換する。[Three.js公式Texture](https://threejs.org/docs/pages/Texture.html)。最終的な行数へ全表示文字のUVを再正規化し、shaderのセル高さと同じ値を使う。1回の入力内や描画を保留した複数入力で何度成長しても、古い文字のUVが以前の行数を参照しないようにする。

明示的なリセット時は1行へ戻す。これは既存のリセット操作で文字の身体を作り直す際の表示資源の縮小で、日付や時間による自動的な入力削除ではない。

## 独立した確認

[`atlas-regression.ts`](atlas-regression.ts)は凍結した候補Aを別クラスとして読み、同じ人工文字・seed・色・時刻・400×440画面で比較する。日本語、英字、記号、NFCへ正規化される合成アクセント、絵文字・旗・肌色・ZWJを含む1,024種類を使う。日本語IMEの検証とは別。

- 1/32/33/64/65/128/129/256/257/512/513/1,024種類の容量境界。
- コピーしたCanvasの既存画素、文字ID・原文・色・出生時刻、位置・方向・形遷移の一致。
- 実WebGLの球・箱・メビウス・クラゲ・鳥・魚・蛇。
- resetで縮小後に成長を繰り返す経路。
- 33種類→65種類を描画前に続けて受ける経路。全UVが最後の4行に揃うこと。
- 32,000文字保存を1,536表示へサンプルしても、文字履歴を捨てないこと。
- 交換前Textureのdisposeイベント、描画後にrendererが所有するTexture数、GL error。
- 新しいオプションなしの固定atlasとshader。

GPU画素の事前許容誤差はチャンネル最大差2/255、全チャンネル平均差0.01/255以下。Textureの正規化座標が変わるため、同じ字形でもGPUの丸め差を許す条件。Canvasの画素は完全一致を求める。固定経路・文字座標・色等の数値は完全一致を求める。

## 結果と修正

このMacのChrome155 headless、400×440、pixel ratio 1で確認した。[実測JSON](regression-result.json)。単体173件・型検査も成功。

| 確認 | 結果 |
| --- | --- |
| 12種類数の境界 | 予定した1/2/4/8/16/32行へ成長 |
| 境界のCanvas画素、合計66,060,288チャンネル | コピー後も完全一致 |
| 境界＋7形×5回のreset/再成長＋延期入力、計48 GPU条件 | 最大差2/255、最大平均差0.000080/255。事前の許容範囲内 |
| 原文・字形ID・色・出生時刻・座標・方向・形遷移 | 基準と完全一致 |
| 33種類→65種類を描画前に入力 | 全65文字分のUV範囲を合併。GPU画素完全一致 |
| Texture交換・reset縮小後 | 以前のGPU資源へdispose、描画後の所有Textureは両版とも1個 |
| 32,000文字保存/1,536表示 | 保存履歴を保持し、同じサンプルのGPU比較に成功 |
| 新オプションなしの固定atlas | 2,048²を維持。GPU画素完全一致、GL errorなし |
| browser exception・console error | 0 |

初回の「頂点shaderでUVの高さをそのまま変える」候補は、512種類の条件で最大差11/255となり不採用にした。字形Canvasと座標は一致しており、GPUのUV補間・丸めの違いを疑ったが、この原因を独立に証明したわけではない。[初回失敗の記録](first-failure.json)。許容値を変更せず、頂点では以前と同じ固定atlas基準のUVを補間し、fragmentで実際の行数へ変換する方式へ修正した。CPUのUVも行数に揃え、そのUVから固定基準へ変換している。

続く実行では、凍結した候補Aにまだ存在しない`atlas.rows`をハーネスが読んでreset条件を判定し、ハーネス自身が失敗した。基準の実Canvas高さで判定するよう修正した。アプリのreset不具合として扱っていない。

この確認では**OSの実RAM・全体CPUを測っていない**。候補Aの小窓測定は、[局所描画時間と全体資源](../widget-render-budget-v2/README.md)を区別して参照する。主担当が次の別アプリへ統合して、固定atlasとの差を実WebKit上で比較する。

## 再実行

リポジトリrootで`node experiments/widget-atlas-budget-v3/run-regression.mjs`。凍結ソースと比較ページを無視領域へ生成し、別の開発ポート4264で起動する。`dist`や配布アプリは作り直さない。基準は`GLYPH_BASELINE_SHA`、ポートは`GLYPH_ATLAS_PORT`、結果の別保存先は`GLYPH_ATLAS_OUTPUT`で指定できる。

別担当による実WebKit小窓の資源測定と同時には実行しない。実RAMへの効果・長時間の使用・16GBノートPCは別の測定が必要。最大1,024種類まで育てば、固定atlasと同じ論理画素容量になる。
