# 独立した射影・境界のレビュー

2026-10-03。対象は frozen R5 shader と、別版 Metal v2 のカメラ式。ここでの検証は CPU による数値比較であり、実際の GPU・字形 atlas・窓の描画品質の確認とは分ける。

## 半径の上限

`source-snapshot-r1/` と `source-snapshot-r2/` の shader は SHA-256 が同じ。位置・接線・文字平面・吸収・色の式は変更されていない。

| 形 | 位置の式から得られる上限 | カメラで使う上限 |
| --- | ---: | ---: |
| 球 | 1.2 | 1.2 |
| L12 の箱 | 3^(1/2 − 1/12) = 1.5805219179 | 1.59 |
| 動くメビウス | hypot(1.58 + .47×1.18, .47×1.18 + .34) = 2.3144818686 | 2.32 |

球の shear は座標の二成分を回転するので、中心からの距離を保つ。shader で描画時に 1.2 倍する係数を含めた。箱は球を L12 ノルムで割るため、L12 単位面と L2 ノルムの関係から上限を得る。

メビウスの材料座標 q は [−1,1]、流れによる drift は [−.47,.47]。`(q+drift)/(1+q*drift)` は [−1,1] を保つので、帯の幅座標 w の絶対値は .47 以下。中心環の半径は 1.58 以下、幅係数は 1.18 以下、縦の中心変位は .34 以下。平面内の半径と z の絶対値を別に上から抑え、上表の保守的な球状の境界を得る。半径の標本走査で見つかった最大値はこの解析上限の証明には用いない。

形変更中の中心位置は旧・新の位置の凸結合なので、その半径は旧・新の半径の同じ凸結合以下。formation と scale を掛ける。count=1 の中心の微動には .04×scale を別に加える。

## 文字の四隅を含む距離

shader の自由に回る文字平面と、正規化・直交化した表面の接平面は、ともにノルムを増やさない。両者の補間も凸結合。文字の四隅は一辺 1 の quad であり、最大 pulse=1.06 を掛けた半径は `glyphSize×1.06/√2` 以下。実際の不透明な字形部分ではなく、atlas セル全体を抑える。

視野角 43°、横に片側 16px、縦に片側 40px を空ける frustum の小さい方を θ とする。カメラ距離 D に対し、中心半径と quad 半径の合計 R が `D×sin(θ) ≥ R` を満たせば、その球状境界は安全な視野内へ入る。

seedFocus により字形の大きさの一部が距離 D に比例するため、R は `fixedRadius + distanceFactor×D`。これを D について解いた式が `minimumDistance`。毎文字の射影や毎フレームの CPU 配列更新で境界を探す方式ではない。

R1 では奥側の切断面が固定値 100 だった。横・縦の収まりとは別に、縦に極端に長い窓で大きくなった D がこの値に近づく／超える失敗を独立検証が検出した。R2 は同じ R の上限から `far=max(100,D+fixedRadius+distanceFactor×D+1)` を使う。回転後の奥側深度は D+R 以下なので、定着文字の境界に 1 の余裕を持つ。R1 の失敗原票は保持する。

## 静的な更新経路

両版の `Renderer.swift` を読み、次を確認した。

- `displayed = matter.displayed()`、Core Text atlas の更新、`displayed.map` による instance 配列、`device.makeBuffer` は `rebuild()` の中にある。
- `draw(in:)` は時刻・視点・scalar easing・カメラ下限・投影行列を計算し、176 bytes の uniform と既存の instance buffer を使う。
- 描画は 1,536 文字でも一回の instanced draw。instance は 80 bytes/文字。shader 内で材料座標から面の位置と接線を計算する。
- v2 の追加は形の半径と定数個の scalar 演算。毎文字の CPU 位置配列の更新は追加されていない。

この読み取りは性能の実測ではない。計測用の小さな配列・診断出力もあるので、CPU がゼロ、GPU が無負荷、常駐資源予算を達成したという意味にはしない。

## 保証を区切る

境界式の対象は、対応する最小サイズ以上の窓、既定 zoom=1、定着した body とその quad。手動の視点回転は球状境界を変えない。入力直後の intake 軌道や画面下部の入力位置、手動 zoom<1 はこの対象に含めない。

count/formation/seedFocus/scale を相関なしで組み合わせた stress は、数値の有限性を確かめる追加条件。アプリで実際に到達できる履歴とは別に集計する。極端縦長の条件も通常の小窓とは分けて報告する。

CPU oracle は frozen `SurfaceReference.swift` の Double 演算と、shader の文字平面・回転式を移植したもの。材料座標は実装の `metalMaterial` を使い Float32 に丸めた値。カメラ式そのものは frozen production Swift の Float32 関数をコンパイルする。shader の Float32、Core Text の日本語・emoji の画素、透明度、実窓のフレーム数、RAM・電力はこの検証では測らない。

画面で body が小さく見えるのは、同じ形を遠くから見るため。端の収まりを改善した事実から、字形の読みやすさや見た目の好みまで改善したとは断定しない。
