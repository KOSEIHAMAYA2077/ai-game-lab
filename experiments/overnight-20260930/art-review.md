# 文字アートの独立レビュー

2026-09-30。v0.5.0を対象にした約10分のレビュー。ソースは変更していない。AGENTS、README、WORKFLOW、BRIEF、今回のSTATUSと、model.ts・shapes.ts・scene.tsを読んだ。既存の凝縮・メビウス表面・32,000文字の画像を確認し、別の一時Chromeで1・4・16・64・512・4,096文字を実際に描画した。既存の試遊タブは操作していない。

## 観察

条件: 1440×1000、初期seed=1、凝縮/表面、初期@に「あ」を足して指定総数、倍率1、投入後に開発用時計を10秒前進、標準カメラ。実OSの日本語変換操作を検査したものではない。

| 総数 | 画面の観察 | カメラ距離 / スケール |
| --- | --- | --- |
| 1 | 近くの@。字形として認識できる | 3.80 / 1.00 |
| 4 | 字が直径およそ550pxへ飛び散り、各字は約20〜30px。集合が育った感じが薄い | 4.54 / 1.01 |
| 16 | 球を推測するには空白が多い。幾つかは真横になり細い線になる | 4.74 / 1.06 |
| 64 | 周囲の輪郭が少し見えるが、まだ散らばった字の印象 | 5.34 / 1.21 |
| 512 | 球の輪郭が分かる。縦に似た姿勢の文字が並ぶ筋が目立つ | 7.25 / 1.68 |
| 4,096 | 表面になる。ただし縦筋と前後の重なりが強く、均質な膜ではない | 9.76 / 2.29 |

スクリーンショットは一時領域へ保存し目視した。公開証跡として残す比較画像は主担当が最終条件を統一して撮る。面白さ、心地よさ、読みやすさの本人評価はしていない。

原因は三つある。

1. **1→2の寸法断差。** `scene.ts`は1文字だけ104px相当の文字平面を使い、それ以外は一律0.145ワールド単位へ切り替える。さらにカメラへ0.7を加え、座標は完成した球の全面へ広がる。数が少ないほど小さく疎らに見える。
2. **字形の姿勢と位置の意図しない相関。** 位置の方位は `a=fract(i*0.618...)`、姿勢のphaseは `i*2.399963...`。`0.618...*2π + 2.399963... = 2π`なので、方位とyawは初期にほぼ逆相で結び付く。同じ経度付近の文字が似た向きとなり、少なくとも今回の球では縦の筋が生じる。phaseは独立した疑似乱数ではない。
3. **形の表面と文字平面が無関係。** 各文字の中心は形の関数へ従う一方、平面の基底は形の接線や法線へ従わない。帯・球・面に載る文字というより、中心点だけが形に沿った紙片になる。メビウスのねじれの分かりやすさを弱める要因と考えられる。

## 比較する改善候補

### A — 少数文字の集合と寸法を連続させる（最優先）

1文字の大きさから段階的に小さくし、1〜16文字は完成球より小さな範囲へ凝縮する。64〜512文字に向けて半径を開く。字が増えると身体が育つ、という因果に沿う。どの数でどの半径にするかは実装判断でよく、機能やゲームルールは足さない。

比較: 1→2→4→16→64→512の同一入力、同一seed、同一経過時間。静止画像に加え、1文字ずつ3回投入する通常速度の動きを見る。

採用: 1→2で元の@が突然豆粒にならない。4字が一つの存在としてまとまり、16字で全員が同時に重ならない。512字で従来の面の広さを失わない。世界座標だけでなく実画面の大きさで判断する。

### B — 姿勢の相関を外し、密度に応じて流れ/表面へ沿わせる

**B0（小さく試す）:** `phase`を`randomUnit(id + seed)*2π`等、位置とは独立の再現可能な値にする。現在のpitch/yaw/roll/拡縮は保つ。球の縦筋が弱まるかを先に比較する。これだけで良くなるなら大きな変更は不要。

**B1（次の比較案）:** 文字の横軸を流れの接線、縦軸を帯の幅方向や表面上の直交方向に寄せる。その基底上に各文字の独立した小さな回転を加える。完全なカメラ正対にはしない。

| 密度 | 提案する姿勢の性格（未採用の初期値） |
| --- | --- |
| 1〜16 | 独立回転を主体にする。回転の正面/裏面付近に長く居て、真横は短く通る速度変化を比較。厚さゼロの消失は残す |
| 64〜512 | 接線フレームへの重みを約0.5から0.8へ連続増加。小さな独立pitch/rollは常に残す |
| 2,048以上 | 約0.8〜0.9を表面/流れへ寄せ、連続する線/膜を優先。ときどき一枚ずつ局所軸で反転し、硬い印刷板にならないようにする |

正面に長く居る回転の一案は、周期角φに対しyawを `atan2(k*sin(φ), cos(φ))` とすること（k<1）。360度の回転と真横の瞬間を保ったまま速度が変わる。これは常時ビルボード化ではなく、世界内の基準姿勢からの回転。

接線フレームの実装を小さく保つには、まず球とメビウスに限った比較でよい。球は位置の径方向を法線の近似にできる。メビウスはパラメータu/wで座標を取り、微小差分のdu/dwから横軸と幅方向を作る。時刻差分だけだと変形の速度も混ざるため、必要なら形のパラメータを明示した関数に分ける。idの差分はa/bが同時に変わり、fract境界もあるので接線の代用にしない。メビウスは4πを一周とする現行の連続性を保ち、継ぎ目で法線の符号を無理に統一しない。

比較: 同じ512字で「表面 球体」「流れる 球体」「表面 メビウスの輪」「流れる メビウスの輪」、さらに4,096字の表面メビウス。t=8/13/21秒の3時点と20秒の通常再生。カメラ角・入力・色・文字数を揃え、B0とB1を混ぜて評価しない。

採用: 球では筋が減り、メビウスでは帯の幅・反転が分かる。流れる版は細い経路、表面版は幅を持つ膜に見える。真横で消える文字は残るが、全体が一斉に消えない。姿勢の変更で字の種類・色・数は変わらない。

### C — 高密度だけ奥側の重なりを弱める（Bの後、必要なら）

現行はdepthTest/depthWriteがともにfalseで、奥の字も前へ重なり、白い密集が飽和する。既存32,000文字の帯では線・面への成長自体はよく分かるので、ただちに不具合とは扱わない。Bで膜として分かるなら現状を残す。

比較候補は奥側の明るさ/アルファを穏やかに抑えるだけとし、深度書き込みを一括で有効にして文字四角形同士が欠ける実装は避ける。4,096/32,000文字のメビウスと球を同じ時刻で比較し、ねじれの前後が分かりやすくなる場合だけ採用。ユーザーが好む光る網/血流のような印象を消すなら不採用。

## 主担当への推奨

A → B0 → 必要ならB1の順。新しい形を追加する前に、現在の文字数と姿勢だけで「字が集まり、面に育つ」という核が読める状態へする。Cは今回の3時間に必須ではない。少数4文字だけで完全なメビウスを認識できることを要求せず、字の存在感と成長の連続性を合格点にする。

## B1の姿勢補間の追加確認

主担当が球/メビウスの接線基底を実装へ接続した後、基底のquaternionを `w >= 0` にそろえてidentityとnlerpする案に、不連続を確認した。基底が180度を跨ぐと代表quaternionの符号が切り替わり、重みが0/1以外では文字の実際の姿勢も跳ぶ。前フレームとの符号合わせだけでは、identityとの補間重み0.5・quaternionが-identityとなる別の特異点を解消できない。

今回採る比較は、quaternionで回した頂点と元の頂点を混ぜる `p' = (1-a)p + a R p`。quaternionの符号に依存せず、連続した基底に対して頂点も連続する。これは剛体の回転補間ではなく、途中に縮みとせん断を含む。少〜中密度では文字が一時的につぶれることを許容するという主担当の判断で採用候補となった。

数値確認条件: 単位回転軸normalize(1,2,3)、単位頂点(1,0,0)、180度の前後±0.000001rad。JavaScript倍精度で旧方式の姿勢差、新方式の頂点距離、qと-qの一致を計算した。

| 混合重みa | 旧方式の姿勢の跳び | 新方式の頂点距離 | qと-qの差 |
| --- | --- | --- | --- |
| 0.30976（64字の定常値） | 96.6767度 | 0.0000005970 | 0 |
| 0.5 | 179.9999度 | 0.0000009636 | 0 |
| 0.88（高密度上限） | 31.0608度 | 0.0000016960 | 0 |

位置混合の縮尺の下限は `abs(1-2a)`。高密度のa=0.88では0.76以上だが、a=0.5で180度回転が重なると一時的に0までつぶれ得る。これを剛体回転として説明しない。数値的な連続性を確認したもので、最終的な見た目の評価は主担当のブラウザ比較へ委ねる。
