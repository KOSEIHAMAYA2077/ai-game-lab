# 形を失わず、動きだけを変える独立設計

2026-09-30。既存 `shapes.ts`・`language.ts`・`model.ts`・`scene.ts`・`diary.ts`を確認した設計メモ。既存アプリとモデルの重みは変更していない。数式の独立実験は[motion-study.ts](motion-study.ts)。画面での見え方・本人の面白さは未評価。

## 採用の順番

**まず呼吸と波を、形とは別の指定として足す。次に団子を既存球面の組み合わせとして足す。雨は一時的な非表示の処理まで入れられる時だけ採用する。**

現在は `mode=flow/surface` が文字の分布を、`deformation=gentle/omega/double` がメビウス等の変形を表す。ここへさらに雨や呼吸を詰めず、独立した `motion` を一つ追加すると、`表面 呼吸 立方体`・`流れる 波打つ メビウス`を組み合わせられる。最初は `calm | breathe | wave | rain` の選択式で十分。複数の運動候補がある文は、既存の形・色と同様、送信時のseedから一つ選ぶ。毎フレーム選び直さない。

形の位置 `P(id,t)` を先に計算し、呼吸と波はその後の座標変換にする。ただし複数個・鎖の配置より前に適用すると、群れの中心までふくらんだり鎖がほどけたりしにくい。呼吸だけは全体へ適用しても形状の相似性を保つ。入力された文字・追加時刻・指定色・既存文字はそのまま維持する。

## 三つの数式

| 試したい入力 | 座標の作り方 | 保持できる性質 | 数値・判断 |
| --- | --- | --- | --- |
| `表面 呼吸する 黄色 立方体` | `s(t)=exp(0.12 sin(0.75t+φ))`, `P'=sP` | 角、直線、各辺の比率。立方体が単に丸くなることはない | 周期8.38秒。大きさは約0.887～1.127倍。文字ごとに違う位相を与えず、形として呼吸する |
| `流れる 波打つ メビウスの輪` | `θ(y,t)=0.20 sin(1.7y−0.8t)`。`(x,z)`をθだけ回しyは保存 | 原点からの距離を保存。逆変換できるので、連続面を裂かず同一点の継ぎ目も一致する | 形全体を柔らかくねじる。既存メビウスのねじれ位置移動へ上乗せ。独立粒子ノイズを使わず、面のまとまりを保つ |
| `表面 雨 水色 球体` | `q=fract(b_id+0.12t)`, `y=1−2q`, `r=√(1−y²)`, `P=1.2(r cosφ,y,r sinφ)` | 文字は球面から外れず、上から下へ流れる。y一様分布なので面積密度も一様 | 一周8.33秒。下端→上端の飛び移りは両端5.5%区間で透明にする必要がある。球体限定でまず試す |

呼吸のφは場のseedから固定してよい。波は初回係数0.20radを上限とし、立方体を見て角が読めなければ0.12へ下げる。既存の形の時間運動を止める必要はないが、球体はもともと小さな呼吸を持つので、二重の呼吸が気になったら追加側だけの振幅を弱める。

雨の不透明度は `smooth(q/.055) × smooth((1−q)/.055)`。既存shaderに運動用の不透明度を一つ追加し、文字アトラスのalphaへ掛ける。移動のリセットを見せたまま「雨」にしない。数式上の位置そのものは極を跨ぐ時に不連続なので、「連続軌道」とは呼ばない。文字の種類・IDを消す処理でもない。

**雨を全形状へ単純にY減算するのは採らない。** 立方体・メビウスの形から文字が離れてしまう。初回は球体だけを対応条件として短く案内するか、雨自体を独立した現象にする。球体以外への投影は形ごとの座標系と境界処理が必要で、今夜の必須にはしない。

## 団子は学習を待たずに試せる

3個の半径0.46の球をY方向 `−0.88, 0, +0.88` に配置する。既存IDを `group=id%3`, `local=floor(id/3)` で分け、各球の表面を異なる速さで循環させる。少量の文字でも一つの球へ偏らない。文字は元の入力をそのまま使い、団子の画像・素材は不要。

`だんご | 団子 | dango` を手書き形状の語として追加できる。凍結モデルへラベルをこっそり追加せず、花火と同様の明示的な形として扱う。分類モデルが団子を学習できたとは報告しない。今の `chain` は `ring` を強制するため、団子を鎖で実装すると既存解釈と衝突する。

実装を小さくするなら `shape=dango` を一つの複合形として持ち、`だんご 2個`は三玉の組を二つ出す、とHELPに示す。`球体 3個`は従来どおり群れ、団子は縦の三玉で区別する。より一般的な部品・配置データへ移すのは別の小実験でよい。

## 語彙と状態の衝突

- `流れる`は既存の `mode=flow`。`波打つ`をflowの別名にせずmotionとする。`表面 波打つ 球体`も成立する。
- `波`だけでは「電波」「余波」まで拾う。最初は `波打つ | うねる | wave`、呼吸は `呼吸 | 息づく | 脈動 | breathe`くらいに絞る。日本語の部分一致は現在の仕様だが、短い一文字をむやみに増やさない。
- 英語 `wave` は `microwave` と衝突する。英語語彙だけ単語境界を付ける。日本語語彙へ `\b`を付けない。
- `雨`は「雨上がり」にも反応する。否定・文脈理解をしていないことは既存方針と同様。「今日は雨だった」のような執筆反応にはむしろ自然だが、`雨ではない`を正しく理解したとは扱わない。
- 将来 `花`を足す時は `花火`を二重に拾わない。既存の最長一致 `wordChoices`を使う。`メビウスの輪`の輪との重なり除去も維持する。
- `呼吸する 波打つ 立方体`は送信時に一つの運動を選び、選んだ結果を短く表示。最初から任意の運動スタックを作る必要はない。
- 運動の未指定は現在の運動を継続すると、色だけの追加入力で動きが失われない。`普通`・`通常`などで運動だけを戻す操作が必要。これは時間を停止する既存ボタンとは分ける。
- 旧日記にはmotionがない。読込みでは `motion ?? 'calm'`へ正規化し、未知のmotion値は拒否。復元と再書出しも確認する。現在の`validDay`は形・mode等を個別検査するため、型だけ足しても互換性は完成しない。
- `setForm`で形ボタンを押した時にmotionを維持するか解除するかを統一する。提案は維持。リセットでcalmへ戻す。

## 独立した数値確認

`node experiments/overnight-20260930/motion-study.ts` をNode 26.4.0で実行。256個の位置を20秒間60Hz相当、合計307,456点で確認した。

- 呼吸の拡縮範囲: 0.886920437～1.127496844倍。非ゼロ座標の倍率が一致。
- 波の逆変換誤差最大: `3.14e−16`。半径差最大: `4.44e−16`。形の継ぎ目は同一座標へ同一変換をする設計上維持される。
- 雨の球面半径誤差最大: `4.44e−16`。折返し以外の307,424比較でYが下向き。alphaが0.5を超える点は約94.5%。
- 団子の各球の半径誤差最大: `1.67e−16`。同じID・時刻・seedの再計算は一致。

これは数式の健全性の確認で、見た目の良さ・実アプリへの統合・性能を検証したものではない。独立ファイルはアプリからimportしていない。

## 第二巡: 呼吸・波の実装候補

rootの追加依頼により、以下の**新規ファイルのみ**を実装した。既存の`shapes.ts`・`language.ts`・`diary.ts`・`scene.ts`への統合は主担当が行う。雨は今回の実装候補から外し、団子は上記の独立式だけ残した。

- `src/motions.ts`: `Motion=calm|breathe|wave`、毎フレーム一回の`prepareMotion`、座標変換・逆変換・接線変換・位置と2接線の一括変換。
- `src/motion-language.ts`: `motionChoices`による候補抽出、`interpretMotion`による未指定維持・明示calm解除。日本語は語彙トリガー、英語は単語境界を使用。入力文字列自体は変更しない。
- `src/motions.test.ts`: 5件。呼吸の相似性、波の半径保持と逆写像、位置の中央差分と接線微分の一致、変形後法線の直交性、インプレース出力再利用、複数候補、英語の部分語誤認、未指定と解除を確認。

```ts
// Reuse these objects across frames/glyphs.
const motion = prepareMotion('calm', 0);
const positionOut: Vec3 = [0, 0, 0];
const xOut: Vec3 = [0, 0, 0];
const yOut: Vec3 = [0, 0, 0];

// Once per frame:
prepareMotion(spec.motion ?? 'calm', time, motion);
// Once per glyph, using the ORIGINAL position and surface frame:
applyMotionFrame(motion, position, frame.x, frame.y, positionOut, xOut, yOut);
// Renderer: normalize xOut, Gram-Schmidt yOut, then z = cross(xOut,yOut).
```

波では位置だけでなく微分も変換する。角度を`θ(y)`、変形済みの座標を`(X,y,Z)`とすると、接線`(u,v,w)`は

`(cosθ·u−sinθ·w−Z·θ'(y)·v, v, sinθ·u+cosθ·w+X·θ'(y)·v)`

になる。単に接線を同じ角度だけ回すと、縦方向に曲がった面から文字平面がずれる。法線は接線と異なる変換なので、法線をそのままこの関数へ渡さない。`applyMotionFrame`は出力3本が互いに異なる配列であることを前提とし、それぞれの入力と同一の配列でも安全。旧位置を全て読み取ってから書き込む。

`npm test -- src/motions.test.ts` は5件成功。Node 26.4.0で、10フレームのウォームアップ後に32,000個×200フレームの一括変換を測る単独計測を一度実施し、278.1ms（平均約1.39ms/フレーム）だった。座標の準備や描画を含まない単独CPU計測であり、ブラウザの実FPS・32k全体の性能を保証する数字ではない。
