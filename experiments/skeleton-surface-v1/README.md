# Glyph Matter — 文章から骨格と文字の表面へ

保存済み根性版 v0.11.0-rigs.1 の表示を土台にした、独立した v0.12 比較版。**小型モデルの入力解釈から、形の構築・文字配置・吸収の終了まで動く。** 既存の試遊版と保存領域は保持している。

## 試す

`prototypes/glyph-creature` で `npm ci --ignore-scripts`、`npm run dev`。`http://127.0.0.1:4212/skeleton.html` を開き、Enter → 文章 → Enter。

HELPの「小型モデルを準備」で、無料の多言語MiniLM int8モデルを公式配布元から約128MB取得する。SHA-256を確認してブラウザに保存し、WASM CPUのWorkerで処理する。入力は外へ送らない。初回準備は通信速度にも依存する。根性版はモデル取得なしで使える。ローカルPython CPUとの比較を行う場合は [起動方法](server/README.md) を使う。

`細長い花瓶`、`すらっとした花入れ`、`曲がった赤い剣`、`ねじれた輪っか`、`黄色いメビウスの輪` を試す。文章を変えて首・幅・曲がり・ねじれを見る。元の文字は材料として残り、指定色は新しく加えた文字だけに適用する。HELPの倍率は文字の繰り返しによる表示密度。独立版では最大8,192文字。

## 実装の範囲

モデルは6系統の意味検索と限定した属性を担う。形のパラメータには制約を設け、手続き的な骨格・曲面を作り、その面に文字を配置する。完全一致の辞書・明示属性のルール・学習済み埋め込みの判断を [証拠として分ける](server/README.md)。汎用のtext-to-meshモデルや、未知の自由な骨格を学習で出力するモデルではない。

花瓶は外壁・空洞の内壁・口縁・底板。剣は刃・鍔・柄。メビウスは半ねじれを保った動く帯、普通の円環は閉じた管。球と箱を対照に置く。厚さゼロの文字平面を面の接線へ沿わせ、近い面の文字を表示する。流れは低周波の手続き的な変化で、物理的な流体シミュレーションではない。

## 初回と回帰の結果

独立担当が先に凍結した人工30文で、初回は形27/30、形＋属性26/30。誤ったメビウスの名詞分解と「細身」の語形を直した後、同じ30文で29/30。後者は**回帰確認**で、新しい未見精度ではない。紙の帯を半回転して貼り合わせる説明はまだ保留する。通常文・未対応語から勝手に別の形を作らないことも別に採点した。

起動済みローカルCPUモデルを使ったブラウザの実入力では、30文すべてが文字の吸収まで終了し、中央値3.983秒、p95 3.988秒。作成すべき新形は25/26、通常文・未対応の正常保留は4/4。モデルだけでなく、表面構築・文字配置・初回新フレーム・約4秒の吸収演出を含む。最初の新フレームは移行途中なので、完成形の時間には吸収終了の `totalMs` を使う。[初回評価](evaluation/INITIAL_REPORT.md)・[回帰](evaluation/REGRESSION_REPORT.md)・[全工程記録](evaluation/browser-regression-1.json)。

ブラウザ内WASMでも同じ30文の意味一致29/30、CPU版と一致。解釈の中央値29.65ms、p95 51.81ms。実際のUIで試した4文では、入力から吸収終了まで4.006〜4.015秒、文字保持4/4、推論・描画中の外部リクエスト0、ページエラー0。初回約127.5MBの公式モデル取得＋準備は8.824秒、キャッシュ後の準備は1.743秒・再取得0Bだった。準備が済んでいない状態で送信すると、その待ち時間も今回の全体時間へ入る。先にHELPで準備した場合は、準備時間を別に表示する。[WASM実UI記録](evaluation/browser-wasm-ui-1.json)。

計測機はApple M5/32GB。16GB Windows laptop CPU/iGPUの実測とは扱わない。4倍の人工CPU抑制でも一例は4.017秒で成立したが、対象PCの性能やRAM容量の再現ではない。
