# ブラウザでの生成・表示までの確認

人工入力をブラウザの入力欄へ入れ、Enter で送信した。解釈 JSON を受け取った時点で終わらず、骨格・表面の構築、文字配置、表示と吸収演出の完了まで、実際の時計で測定した。

対象は Apple M5・32GB 上の Chrome。開発用画面 1440×1000、測定中は一つのページを表示。16GB の一般ノート PC で確認した結果ではない。OS の日本語 IME による変換確定操作は今回の自動確認に含まない。

## CPU API 版：30 入力

[生結果](browser-regression-1.json)。入力ごとに新しいページを使い、起動済みの端末内 CPU 推論へ接続した。最大 8,191 個の文字平面を配置した。

- 入力→解釈→骨格・表面→文字配置→吸収完了: p50 **3.983 秒**、p95 **3.988 秒**。
- 30 入力とも 10 秒以内。意図した新しい形は **25/26**。通常文・未対応対象を正しく保留したものは **4/4**。
- 形＋属性の一致は 29/30、文字の保持 30/30、有限な座標 30/30、ページ例外 0。

紙の帯を半回転して端を貼る説明は、メビウスに確定できず保留した。これを新しい 3D 生成の成功とは数えない。初回の独立評価を見て修正した後、同じ fixture を使った**回帰確認**。

`firstFrameMs` は新しいデータを設定した直後の最初の描画で、その時点の形は形成途中。完成までを含む値は `totalMs`。約 3.95 秒の吸収・変形演出を含むため、解釈時間だけと混ぜない。モデルプロセスの初期準備は起動済みで、上記には含まない。

## ブラウザ内 WASM：意味の実装差

[生結果](browser-worker-regression-1.json)、[採点結果](browser-worker-regression-1-scored.json)。同じ固定 30 入力をブラウザ内 Worker の MiniLM int8 に渡し、CPU API と意味の判定が一致するかを確認した。

- 形＋属性の一致は **29/30**。CPU API と同じ紙の帯説明だけが保留。
- 解釈 p50 **29.65 ms**、p95 **51.81 ms**。ここは 3D と表示を含まない。
- 初回の公式重み・tokenizer 127,494,442 B の取得＋準備は **9.809 秒**。キャッシュなし。

CPU 版の結果を見た後の同じ fixture なので、ブラウザエンジンでの最初の実行でも、新しい未見精度とは呼ばない。

## ブラウザ内 WASM：実際の操作と全工程

[生結果](browser-wasm-ui-1.json)。HELP から小型モデルを準備し、ブラウザ内推論を選んだ。花瓶の言い換え→曲がった剣→ねじれたメビウス→横広で背の低い立方体を、同じページで順に入力した。

- 全工程は **4.006〜4.015 秒**。4/4 で指定した形が現れ、過去の文字と入力履歴も 4/4 保持した。
- 初回の取得＋モデル準備は **8.824 秒**。同じブラウザで再読み込み後はキャッシュを使い **1.743 秒**、追加ダウンロード 0 B。
- モデル準備後の入力解釈・描画中の外部リクエストは **0**。取得は固定した公式モデル素材のみで、入力文を外部へ送らない。
- ページ例外 0。

モデル準備は生成と別に測定している。未準備の初回使用はダウンロード時間にも左右されるため、起動から最初の形まで一律 10 秒を保証しない。モデル準備済みの全工程で 10 秒目標を満たした結果。

補助として同じ Chrome の CPU 実行を 4 倍抑制し、縦長で細い球体の入力も 4.017 秒で完成した。これは人工的な負荷試験で、Intel/AMD のノート CPU/iGPU や 16GB 実機の代わりにはならない。GPU の描画性能やメモリ容量を再現する試験でもない。

## 画面で見たもの

6 系統を正面から確認し、花瓶の胴・口、剣の刃・鍔・柄、メビウスの面を文字で判別できた。文字は輪郭だけでなく、面上にも分布している。花瓶は視点をドラッグして傾け、細口・広口とも口縁、穴、内壁を確認した。画像は非公開のローカル検証用に保存している。

「首が細い」で首に加えて胴の幅まで狭くなるように、属性の修飾範囲はまだ粗い。対応済み 6 系統の制約内で形を構築する実装で、未知の任意メッシュを生成できるモデルではない。

## 評価手順の修正

最初のブラウザ試験では、回転している `press enter` ボタンに自動クリックを試み、位置の安定待ちで停止した。モデル生成の失敗ではない。実際の Enter キー操作へ変更して、上記の測定を行った。この診断は [別記録](browser-harness-debug-1.json) に残しており、生成速度や成功率には混ぜていない。
