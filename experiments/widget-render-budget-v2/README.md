# 小窓の描画予算: 候補A

2026-10-03。v0.14の位置・面・骨格を保ったまま、表示容量と計算・転送を見直した比較。基準はcommit `68313962729c03324e32ec3b924020ed30ef4752`。既存の公開タグ・小窓アプリは変更しない。通常CPU5%、RAM200 MiBの達成を意味しない。

変更対象は[`scene.ts`](../../prototypes/glyph-creature/src/scene.ts)。文字履歴を保持するMatterや、文章を解釈するモデル、UI、依存関係は変更していない。

- 表示上限を持つ小窓では、10個の座標・色等の配列も表示容量分だけ確保する。従来ページのオプションなしの容量は32,000のまま。
- GPUの属性は使用範囲だけ更新する。まだ描いていない入力を続けて受けた場合は範囲を合併し、先の入力を取り落とさない。
- 文字の形成・形遷移は同じ計算順序で3成分ずつ処理する。吸収済みの文字には入力元のコピーを作らず、3.7秒経過後には吸収用の乱数計算も行わない。この閾値は全seedの遅延0.2秒未満＋移動3.5秒未満から決めた。
- 表示サンプルが入れ替わっても、文字の自由回転の位相を保存側の文字IDに結び付ける。上限以下では従来の表示位置とIDが一致するため、見え方は一致する。

## 数値・GPUの比較

[`geometry-regression.ts`](geometry-regression.ts)は、凍結した基準ソースを別クラスとして読み、候補と同じ人工入力・seed・時刻・画面で直接比較する。配列名や実装をなぞった期待値を作るのではなく、前の実装が実際に出す座標とGPU画素を基準にした。[結果JSON](regression-result.json)。

| 確認 | 結果 |
| --- | --- |
| 60形、呼吸/波、複数配置、6骨格面、6部位、3関係、吸収中の形変更 | 989フレーム、6,766,826成分を比較。位置・回転・遷移・色・入力元の最大差0 |
| 球、箱、メビウス、クラゲ、鳥、魚、蛇の実WebGL | 各1,536表示。GPU画素は全チャンネル一致、画面は空でない。1draw call、GL errorなし |
| 続けて2入力、描画は後で1回 | 2件を含む色・UVのGPU画素が一致。範囲は1個に合併 |
| 32,000文字の入力履歴 | 保存32,000、表示1,536、同じ文字ID・字形・色・面の位置を保持 |
| サンプル変更後も表示される111文字 | 文字ごとの回転位相を保持 |
| 表示上限を渡さない従来経路 | 配列容量32,000、実WebGL描画成功 |

入力は日本語・英字・記号・合成アクセント・絵文字の人工列。実ユーザーの入力を保存・公開していない。日本語IMEの検証ではない。

| 容量・転送 | 基準 | 候補A |
| --- | ---: | ---: |
| CPUの10個のFloat32Array合計 | 3,200,000 bytes | 153,600 bytes |
| GPUの7属性の論理容量 | 2,048,000 bytes | 98,304 bytes |
| 定着時1フレームの実`bufferSubData`渡し量 | 896,000 bytes | 43,008 bytes |

最後の行はWebGL呼び出しを捕捉した値。それ以外は配列・属性の論理容量で、WebKit全体の実RAMではない。字形atlasは今回固定2,048²のまま。

## 描画関数の所要時間

このMacのChrome 155 headless、400×440、pixel ratio 1、1,536表示、暖機90フレーム、各180フレームをABBA順に測定した。同じ形で基準/候補/候補/基準の2回ずつを測り、下表は2回の平均値。シミュレーション時刻は1/15秒ずつ進めるが、測定ループは実時間15fpsに制限していない。**JS＋WebGLコマンド投入の所要時間**であり、常駐アプリのCPU使用率やGPUの完了時間ではない。

| 形 | 基準mean ms | 候補A mean ms | 基準p95 ms | 候補A p95 ms |
| --- | ---: | ---: | ---: | ---: |
| 球 | 0.779 | 0.508 | 0.900 | 0.600 |
| 箱 | 0.939 | 0.626 | 1.000 | 0.700 |
| メビウス | 0.787 | 0.504 | 0.900 | 0.600 |
| クラゲ | 0.959 | 0.646 | 1.000 | 0.700 |
| 鳥 | 1.100 | 0.770 | 1.200 | 0.900 |
| 魚 | 1.154 | 0.815 | 1.250 | 0.900 |
| 蛇 | 1.148 | 0.807 | 1.200 | 0.900 |
| プログラムの花瓶 | 1.326 | 1.006 | 1.400 | 1.100 |

この短い条件ではmeanが24〜36%短縮した。GPUへの投入を省いたgeometry-only測定もJSONへ残し、そこでも23〜39%短縮した。ただし、Mac小窓で測ったWebKitのCPU/RAMや16GBノートPC実機へ、この改善率をそのまま移さない。レンダリング以外の固定費、合成、ドライバ、モデル処理は別に測る。

## 再実行と残る課題

依存関係が揃ったリポジトリのrootで、`node experiments/widget-render-budget-v2/run-regression.mjs`。基準ソースと比較ページは無視領域へ生成し、別の開発ポート4263で測る。基準指定は`GLYPH_BASELINE_SHA`、ポートは`GLYPH_BUDGET_PORT`、結果の別保存先は`GLYPH_BUDGET_OUTPUT`。`dist`や配布アプリを再生成しない。

候補Aの数値チェックは合格した。同じ人工身体の実WebKit比較は、基準→候補→基準再測定の90秒×3窓でCPU13.278→12.110→11.798%、charged footprint中央値218.93→207.60→215.39MiB。CPU全体の改善は再確認できず、RAMが低い観測値に留まる。[条件・失敗窓・原票](native-evaluation/REPORT.md)。数値微分を使う形の5回の曲面評価は残る。[5Hz面評価と15fps補間の別候補](../widget-companion-v1/render-budget-plan.md)を、近似誤差と見た目を含めて比較する。

暫定のテストは単体161件・型検査とも成功。最初のハーネス実行でfaviconの404をconsole errorとして拾ったため、比較ページへ空のfaviconを与えて測定をやり直した。アプリの不具合として扱っていない。

## v0.14.1の保存と診断

表示容量が残り23文字の場合にも、送信された原文を切らずにバッチへ残す。人工入力3件を実UIで送信して32,000文字へ達し、1,536表示と旧色・全原文のreload復元を確認。[再現](raw-capacity-check.mjs) / [結果](raw-capacity-result.json)。

native R3は停止等のboolean状態が変わる最終メッセージを、通常1秒の診断保存制限から除外する。実ボタンで停止→再開→停止後、表示中5秒と、停止を解除した実Hide5秒の両方でフレーム固定・正しい最終状態を保存した。[停止](native-r3-smoke.json) / [非表示](native-r3-hidden-smoke.json)。これは診断修正のsmokeで、R3の資源を90秒比較した結果ではない。配布は旧版と別bundle ID・保存originの新規アプリで行う。
