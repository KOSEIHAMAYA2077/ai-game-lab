# WASM の実運用入力に合わせた別 head

公開比較版で使う CPU 学習 head を上書きせず、同じ人工訓練/検証データをブラウザー WASM の batch=1 で埋め込み直した追加実験。独立評価の本文・正解は学習しない。構文規則、6 部品、寸法規則、受理閾値、geometry は変更しない。

## 動機

同じ固定モデルでも、CPU の graph optimization 設定や、一度に埋め込む文数により、出力に差があった。`../backend-diagnosis.json` は CPU none/basic と extended/all の差を記録する。開発用の境界例の関係確率は none/basic 約 0.6007、extended/all 約 0.6624、ブラウザー WASM 約 0.6096 だった。関係のラベルはどれも end だが、0.62 の受理閾値をまたぐ。

ブラウザーでも人工訓練入力を単独か 8 文まとめて計算するかにより、L2 正規化された埋め込みの最大成分差が、開発用 8 例で約 0.013〜0.0215 あった。旧 head は CPU batch8 の学習入力、実際の文章解釈は WASM batch1 である。tokenizer だけの問題とは断定しない。量子化推論の backend と入力バッチの違いを、配備時の再現条件として記録する。

## 学習と凍結

人工訓練 1,103 文・検証 288 文を、マスク済みの 57 種＋12 種の入力へ変換。生文もマスク済み入力も、訓練/検証の完全一致は 0 件。69 種を 1 文ずつブラウザーで計算した。初回公式資産の取得・検査・初期化は約 7.35 秒、69 入力の埋め込みは約 0.804 秒だった。実測は Apple Silicon Mac / インストール済み Chrome であり、一般的な Windows 16GB 端末は未実測。

線形 softmax の学習率 0.06、L2 0.007、訓練受理条件・検証受理条件・上限 1,200 epoch は旧 head の設定を引き継いだ。選択 epoch は 12。選択した head は人工訓練/検証のクラス分類が 100%、検証の受理条件込みで 87.5% だった。これは旧 head の人工検証受理率を超えておらず、配備向けに計算条件を揃えたこと自体が品質改善を保証するわけではない。

head SHA-256: `af2289c3bccb20d0186fa2770460ba50b2d08413209ab5f866c0ae2aeff1203d`。

元の head は `../relation-head.json`、新 head はこのディレクトリの `relation-head.json`。初回の独立 challenge は評価担当が学習完了前に別途凍結し、本文を学習担当へ渡さずに比較する。このフォルダーの学習結果だけで新 head を公開版へ採用しない。

追加の独立 challenge 8 文では元 head と新 head がともに 8/8（7 構造＋1 保留）だった。関係 head が動いた 7 文で、新 head の確率はすべて元 head より低かった。この新規セットで精度の優位性は示せていない。どちらも成功した少数例から任意文へ一般化できるとは言わない。旧 fixture に対する追加比較は回帰結果として別に記録する。独立採点の正本は `../../evaluation/head-challenge-first.json` を参照する。

既知の 44 文の回帰比較も合計は同率 39/44 だった。元 head は 28/30＋6/6＋5/8、新 head は 29/30＋6/6＋4/8。新 head は境界の接続文を受理できた一方、既存の貫通文を保留する退化があった。改善の根拠がないため公開アプリへ採用しない。この head と計算記録は、不採用の比較実験として残す。ここでの採点は構造の意味だけで、geometry 側の対応範囲や実 UI の結果とは別である。

## 再現と独立評価の方法

`prepare.py` は元の人工訓練/検証ファイルだけを読む。`encode.mjs` は固定した公式ファイルの hash を確認し、ブラウザーで埋め込みを作る。ダウンロードへ入力本文を送らない。`train.py` は得られた人工文のベクトルだけから別 head を学習する。

独立評価には、評価担当が本文だけの JSON list を作る。`calibrated_model.py --texts ... --queries ...` が、固定した controller の解釈に必要なモデル入力を列挙する。`encode.mjs <queries.json> <embeddings.json>` へ渡し、最後に `calibrated_model.py --texts ... --embeddings ... --head ... --output ...` で解釈する。元 head と新 head を同じ WASM の入力ベクトルで比較できる。

参考の caption / descriptor / background は、公開 Worker と同じ順番の batch8 で別に計算する。文章の実運用 query だけを batch1 にする。モデル入力の対照条件を変えずに head の違いを比較するためである。

この手順の `modelMs` は保存済みベクトルの lookup 後の時間であり、実際のモデル推論・geometry・文字描画を含む時間ではない。全工程性能の根拠には使わない。本番 Worker と異なる Chrome の実行文脈にある追加実験なので、採用前には本番 Worker での再確認が必要。

人工文のベクトルと自作 head の利用条件は、リポジトリの配布条件に従う。元エンコーダーの出所・Apache-2.0・固定 revision / SHA は [元のモデル記録](../README.md) を参照する。
