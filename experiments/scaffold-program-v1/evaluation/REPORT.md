# 独立評価 — scaffold program v1

文章から有限の部位と関係を解釈し、中心線・断面から作った面へ文字を載せる試作を評価した。任意のメッシュを生成するモデルではない。最大2部位、6種類の基本形、1つの接続関係という範囲を固定している。

## 意味の評価

開発担当者と別に作った日本語・英語の人工例文を、モデル完成前に固定した。30例と、同じ形を2つ使う6例を別に集計する。型だけでなく親子の順序、関係、部位ごとの属性、保留すべき文章を確認した。モデルの型検証と意味の正しさは別の指標である。

| 評価段階 | 基本30例 | 同種2部位6例 | 追加8例 |
|---|---:|---:|---:|
| 初回独立 CPU | 21/30 | 5/6 | — |
| 一般的な構文修正1後 CPU 回帰 | 28/30 | 3/6 | 4/8 初回独立 |
| 読点修正2後 CPU 回帰 | 29/30 | 6/6 | 5/8 回帰 |
| 修正2後の実ブラウザ UI 回帰 | 28/30 | 6/6 | 4/8 回帰 |

追加8例は、修正1のコードが固定された後に新しく用意した。初回の4/8を保存しており、修正後の5/8は回帰結果である。後の高い数値だけを未知の文章への正解率として扱わない。

初回に残った失敗は主に、部位の切り出しや否定を扱う規則だった。修正1では、日本語の読点によって同じ形2部位を1部位へ潰す退化が生じ、修正2で解消した。修正2でも「先っぽ」「At the very tip of…, attach…」「下にして、その上に…」という新しい構文は保留された。意味は近くても任意の表現を理解できる状態には達していない。

学習された関係ヘッド、部位意味の埋め込み、構文規則、明示属性規則の証拠を個別に残した。初回の23関係要求のうち、関係ヘッドまで到達したのは16例で、その条件付きトップラベルは16/16一致だった。これをパイプライン全体の成功率とは扱わない。

固定した元の例文に、訓練/検証用文章との完全一致はなかった。修正1のマスク後入力でも、全3組の例文について完全一致・大文字小文字を揃えた一致はいずれも0件だった。訓練1103例はマスク後57種、検証288例は12種に減る。完全一致0件は、意味や構文テンプレートの独立を証明するものではない。

CPU とブラウザの出力には差がある。「管の先端に球体をつなげた構造。」の `end` 信頼度が CPU 0.662 に対しブラウザ0.610となり、固定閾値0.62でブラウザだけ保留された。閾値を試験結果へ合わせて引き下げていない。未指定の寸法・ねじれにも埋め込みの差が見られるため、完全一致と必要な意味の一致を分けている。

## 実際の形と動作

修正2の配布ファイルを固定した状態で、44例、連続入力3例、負荷1例の48操作を実行した。48/48で有限値のフレームが描かれ、例外0件、入力解釈中の外部要求0件、連続入力で既存の文字・入力群の保持3/3を確認した。`fill` と Enter の自動操作なので、実際の日本語 IME の確定操作は未確認である。

画面を確認し、球が文字の面として見えること、箱の面と稜線、輪の穴、花瓶の首と胴、太い胴と細い管、大小の球が上に接続する様子を確認した。細い管では文字が重なりやすい。前後の文字が密になるため、貫通する輪の関係は見る角度によって分かりにくい。

独立した数値検証では、ブラウザが実際に作った32 Program を再構築した。有限な表面32/32、上に載せる実材質の接触11/11（0秒・30秒）、箱/球の実体の内外へ子の表面が跨がる貫通5/5を確認した。貫通は境界箱の重なりだけで判断していない。先端接続7/7は中心線端点の配置確認であり、全基本形の組み合わせが水密に繋がるという主張ではない。

語義が正しくても、貫通する子が球・箱・花瓶の場合は現在の幾何コンパイラが対応していない。「A sphere passes through a box.」は言語解釈が正しく、幾何段階で保留される例として分けた。

この評価時点の `twist` は文字を置く曲面座標をずらす再パラメータ化で、箱や刃の断面自体を物理的にねじってはいない。曲面上の文字の移動と、形自体の変形を混同しない。

## 時間と実行環境

Apple M5・32GB の Mac、Chrome・WASM・WebGL2/ANGLE Metal（Apple M5）で計測した。16GBの一般的なノートPC CPU/iGPU実機は未検証。

| 範囲 | 結果 |
|---|---:|
| 初回128MBモデル準備 | 9.225秒（画面操作を含む9.351秒） |
| キャッシュ後モデル準備 | 1.972秒（画面操作を含む2.044秒） |
| 未準備の初回入力→自動取得→吸収完了 | 13.839秒 |
| 修正2の準備済み48操作の全工程 | 3.970–4.015秒 |
| 基本30例の全工程中央値 / p95 | 4.001 / 4.009秒 |
| 約8,000字の合成2例、4倍 CPU 負荷 | 4.109 / 4.120秒 |
| 同負荷の実フレーム間隔中央値 / p95 | 33.3 / 50.0ms |

冷初回は、モデルを準備せずブラウザ解釈を選び、文章を送信する実操作で測った。自動ダウンロード・検証・モデル準備を含め13.839秒だったため、10秒の目標は初回に未達、30秒の許容内である。固定された公式モデル素材への GET だけを確認し、要求本文・URLへの入力文字混入はなかった。

全工程は入力開始から解釈、形・文字の構築、最初の描画、3.95秒の吸収完了を含む。最初の描画は形成途中のフレームなので、完成形の時間とは別に記録した。初回準備時間を無言で生成時間から除いていない。

4倍 CPU 負荷は Chrome の人工的な制限で、16GBメモリやノートPC実機の再現ではない。約30fps中心の動きにはなったが、モデル・GPUの性能保証には使えない。高密度試験3例のうち1例は通常の `and` を部位の並列と誤読して保留した。3例すべてで新しい形が生成されたとは報告しない。

## 記録

- `initial-cpu.json` と `INITIAL_REPORT.md`: 初回独立結果。上書きしない。
- `regression-cpu-1.json` / `regression-cpu-2.json`: 開発へ失敗を返した後の回帰。
- `followup-cpu-1.json` / `followup-regression-cpu-2.json`: 追加8例の初回と回帰。
- `browser-ui-1-scored.json` / `browser-ui-2-scored.json`: 固定配布ファイルの実操作、意味と全工程時間。
- `browser-geometry-2.json`: 修正2の実ブラウザ出力に対する独立表面検証。
- `dense-stress-1.json`: 約8,000字、4倍 CPU 負荷、実フレーム間隔。
- `masked-overlap-1.json`: マスク後の訓練/検証入力との一致監査。
- `cold-submit-1.json`: 初回ダウンロードを含む実際の入力から完成まで。
- `browser-geometry-1-corrected.json`: 修正1の表面検証。先に保存した `browser-geometry-1.json` は twist を物理回転と誤読した分析であり、こちらへ訂正した。古い分析も削除せず残す。

採点器の6テストで、親子反転、同種部位の属性反転、関係だけの誤り、欠損・非有限値・余分な項目を取りこぼさないことを確認した。後続のブラウザ専用ヘッド用にも新しい8例を、学習完了前に別ファイルで凍結した。その結果は上の表へ混ぜない。

## 別のブラウザ専用ヘッド — 未採用

CPU版で学習したヘッドと、同じ人工訓練/検証文章をブラウザWASMの埋め込みへ揃えて再学習したヘッドを、別の8例で初めて比較した。旧・新とも8/8（7要求・1保留）で一致し、新ヘッドの優位性は示せなかった。7関係例の新ヘッドの信頼度は旧ヘッドより低かった。

既知44例の回帰では旧28/30・6/6・5/8、新29/30・6/6・4/8で、合計は双方39/44だった。新ヘッドは先端接続1例を救う一方、以前通っていた球と輪の貫通1例を保留へ退化させた。改善を確認できないため、新ヘッドは試作へ採用していない。

この比較は同一の記録済みWASM query（batch 1）と参考埋め込み（batch 8）を、変更していないPython側の解釈器で使う意味比較である。生のブラウザ実操作や速度の評価ではない。幾何コンパイラの対応可否も別扱いなので、39/44を実画面の生成成功率として使わない。記録は `head-challenge-first.json` と `head-regression-first.json` に保存し、新旧ヘッド・埋め込み・例文のハッシュを残した。
